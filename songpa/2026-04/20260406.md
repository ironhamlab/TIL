#### [학습 내용]

**💡Git의 세 가지 공간 개념**

- 작업 디렉토리(Working Directory) : 폴더가 존재
- 스테이징 영역(Staging Area)
- 저장소(Repository): .git 폴더

</br>
</br>

**💡Git 관련 명령어 목록**

- init : 초기화. '.git' 폴더 만들어짐
- add : 작업디렉토리에서 스테이징 영역으로 올림
- commit : 스테이징 영역에서 로컬 저장소로 올림.
- status : 상태 확인 가능
- log : 커밋 기록 및 해시값 등 확인 가능
- revert / ~~reset~~ : 되돌리기
- push : 원격 저장소에 올리기
- pull : 원격 저장소에서 내려받기
- merge : 브랜치 병합
- pull request


</br>
</br>

**💡실수 되돌릴 수 있는 방법 2가지**

1. revert → 과거의 잘못된 코드를 취소하는 새로운 행동을 하겠다고 기록을 남기는 방식.
2. reset (잘 안씀) → 아예 과거로 돌아가서 그 과거 이후에 했던 내용은 전부 지우겠다. 내꺼에 대해서만 할 때는 편할 수 있겠지만, 협업 시에는 내 커밋 지우려다가 다른 사람 코드까지 다 지울 수 있음. 위험함

⇒ git log로 커밋 해시값 확인한 후에, 잘못된 커밋의 해시값 복사 (앞의 7자리 정도만 해도 됨!)

```
$ git revert 000000000
```

### 😎 오픈소스 포크 받아서 기여하는 법

</br>

</br>

**💡Fork 받은 레포지토리에 Pull request 날리는 법**

1. 레포지토리를 Fork 받는다.
2. Fork 받은 (내 이름 들어간) 주소를 git clone 받는다.

```bash
$ git switch -c feature/my-name
# 내이름.txt 파일 추가 및 내용 작성
$ git add 내이름.txt
$ git commit -m "Feat: 내 이름 추가"
$ git push origin feature/my-name
```

→ GitHub로 돌아와보면 화면 상단에 'Compare & pull request' 버튼이 뜸. 해당 버튼 눌러서 Pull Request 작성


</br>

**💡Git Pull 받는 법**

팀장이 팀원들의 pull request를 다 처리하고 나면, 팀장의 상태와 동일하게 맞춰줘야 하니까 pull 받아야 함

```bash
# 이번에는 (팀장 이름 들어간) 주소를 넣어야 함!
$ git remote add upstream [팀장깃주소]

$ git pull upstream main
```

- 내 저장소 → origin
- 본 저장소(팀장) → upstream

</br>

#### [느낀 내용]

* log나 revert 같은 명령어의 경우 자주 사용하지 않았던 명령어인데 리마인드 되는 느낌으로 다시 배우게 되어 좋았다. 앞으로 자주 활용하고 싶다.
* fork 받은 레포지토리에 기여하는 방법을 잘 몰랐는데, 이번 수업을 계기로 알게되었다.
