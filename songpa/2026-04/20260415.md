### 2-1. 이벤트 핸들링

</br>

* `addEventListener`
    * `element.addEventListener('이벤트종류', 실행할함수)` 형태로 사용하는, 가장 강력하고 유연한 현대적인 표준 방식
    * 하나의 이벤트에 여러 개의 핸들러를 부여할 수 있다.

</br>

```html
<body>
<h1>이벤트 핸들러 등록 및 제거</h1>

<hr>

<h3>방법 1. 이벤트 핸들러 어트리뷰트 (구식)</h3>
<pre>
    HTML 태그에 `onclick` 같은 어트리뷰트를 직접 작성하는 옛날 방식입니다.
    HTML과 JavaScript 코드가 섞여서 유지보수가 어렵기 때문에, 현재는 사용하지 않는 것이 좋습니다.
    </pre>
<button onclick="alert('첫 번째 버튼 클릭!');">방법 1 버튼</button>

<hr>

<h3>방법 2. 이벤트 핸들러 프로퍼티 (과도기)</h3>
<pre>
    요소 객체의 `onclick` 프로퍼티에 함수를 직접 할당하는 방식입니다.
    HTML과 JS를 분리했다는 점에서는 발전했지만, <b>하나의 이벤트에 오직 하나의 임무만 부여</b>할 수 있다는
    치명적인 단점이 있습니다.
    </pre>

<button id="btn2">방법 2 버튼</button>
<script>
    const $btn2 = document.getElementById('btn2');

    $btn2.onclick = function() {
        console.log('온클릭 이벤트 발생!');
    };

    $btn2.onclick = function() {
        console.log('두번째 이벤트 발생!');
    };
</script>

<hr>

<h3>방법 3. `addEventListener` (현대적인 표준)</h3>
<pre>
    `element.addEventListener('이벤트종류', 실행할함수)` 형태로 사용하는,
    가장 강력하고 유연한 현대적인 표준 방식입니다.
    </pre>

<button id="btn3">방법 3 버튼</button>
<script>
   const $btn3 = document.getElementById('btn3');

   // 하나의 이벤트에 여러 개의 핸들러를 부여할 수 있다.
   $btn3.addEventListener('click', function() {
        console.log('addEventListener - 첫 번째 이벤트');
   });

    $btn3.addEventListener('click', function() {
        alert('두 번째 이벤트 수행!');
    });
</script>

<hr>

<h3>이벤트 핸들러 제거하기</h3>
<pre>
    이벤트를 제거할 때는 '어떤 임무'를 제거할지 정확히 알려줘야 합니다.
    따라서 제거하려는 함수는 반드시 이름이 있거나 변수에 담겨있어야 합니다.
    </pre>

<button id="btn4">추가/제거 버튼</button>
<button id="addBtn">임무 추가</button>
<button id="removeBtn">임무 제거</button>

<script>
    const $btn4 = document.getElementById('btn4');
    const $addBtn = document.getElementById('addBtn');
    const $removeBtn = document.getElementById('removeBtn');

    // 제거하기 위한 핵심: 함수를 변수에 저장하여 '참조'를 유지
    const mission = () => {
        alert('특수 임무 수행 완료!');
    };

    // 임무 추가 버튼을 누르면 $btn4에 mission 이벤트 핸들러 함수 등록
    $addBtn.addEventListener('click', () => {
        $btn4.addEventListener('click', mission);
        console.log('btn4번에 임무가 추가 되었습니다.');
    })

    // 임무 제거 버튼을 누르면 $btn4에서 mission 이벤트 제거
    $removeBtn.addEventListener('click', () => {
        $btn4.removeEventListener('click', mission);
        console.log('btn4번에 임무가 제거되었습니다.');
    })

    //익명 함수는 추가는 되지만, 제거할 방법이 없다.
    $btn4.addEventListener('click', () => alert('이 이벤트는 제거할 수 없다!'));
    $btn4.removeEventListener('click', () => alert('이 이벤트는 제거할 수 없다!'));
</script>
</body>
```

### 2-2. 이벤트 객체와 this

</br>

* 핸들러 함수의 첫 번째 매개변수 (이름은 e, event 등 자유롭게)로 이벤트 객체를 받는다.

</br>

* `e.target`: '실제로' 이벤트가 시작된 요소
* `e.currentTarget`: 이벤트를 등록한 요소

</br>

* 결론: `this` 대신 `e.currentTarget`을 사용하자!

</br>

```html

    이 객체는 이벤트 핸들러(우리가 등록한 함수)의 <b>첫 번째 인자</b>로 자동으로 전달됩니다.
    </pre>

    // 핸들러 함수의 첫 번째 매개변수 (이름은 e, event 등 자유롭게)로 이벤트 객체를 받는다.
    // document.addEventListener('click', function(e) {

    //     // e.target: '실제로' 이벤트가 시작된 요소
    //     // e.currentTarget: 이벤트를 등록한 요소
    //     console.log('실제 클릭 대상(e.target):', e.target);
    // });
        
   
</script>

<hr>

<h3>2. 핸들러 내부의 `this`: '사건 당사자'는 누구인가?</h3>
<pre>
    `this`는 '누가 이 함수를 호출했는가'에 따라 가리키는 대상이 달라져서 혼란을 줄 수 있습니다.
    특히 화살표 함수를 쓸 때 주의해야 합니다.
    </pre>

<button id="btn">클릭해보세요</button>

<script>
    const $btn = document.getElementById('btn');

    // 1. 일반 function 함수 사용 시
    $btn.addEventListener('click', function(e) {
        console.log('일반 function');
        // 이때의 'this'는 이벤트를 부착한 요소($btn)를 가리킨다.
        console.log('this:', this);
        // e.currentTarget 또한 이벤트를 부착한 요소($btn)를 가리킨다.
        console.log('e.currentTarget:', e.currentTarget);
        console.log(this === e.currentTarget);  // true
        this.style.backgroundColor= 'green';
    });

    // 2. 화살표 함수 사용 시
    $btn.addEventListener('mouseover', (e) => {
        console.log('화살표 함수');
        // 화살표 함수의 'this'는 바깥 스코프(여기서는 전역 객체 window)를 가리킨다.
        console.log('this: ', this);
        console.log('e.currentTarget: ', e.currentTarget);
    })
</script>

<hr>

<h3>3. 결론: `this` 대신 `e.currentTarget`을 사용하자!</h3>
<pre>
    `function`과 화살표 함수 사이에서 `this`가 다르게 동작하여 생기는 혼란을 피하기 위해,
    현대적인 자바스크립트 개발에서는 일관성을 유지하는 것이 중요합니다.

    <b>e.currentTarget</b>은 어떤 종류의 함수를 쓰든, <b>항상 이벤트를 부착한 바로 그 요소</b>를 가리킵니다.
    따라서 `this` 대신 `e.currentTarget`을 사용하는 것이 버그를 줄이는 가장 좋은 습관입니다.
    </pre>

<button id="best-practice-btn">Best Practice</button>
<script>
   const $bestBtn = document.getElementById('best-practice-btn');

   $bestBtn.addEventListener('click', (e) => {
        const btn = e.currentTarget;

        btn.textContent = '클릭되었습니다!';
        btn.style.backgroundColor = 'skyblue';
   })
</script>

</body>
```

### 2-3. 이벤트 전파와 위임

</br>

* 이벤트 버블링: 연못의 파문처럼!
    * 하위 요소에서 발생한 이벤트는, 그 파문이 부모 요소를 따라 최상위까지 올라가는 '버블링' 현상을 일으킴
    * 따라서 부모 요소에 달아둔 이벤트 리스너는, 자식 요소에서 발생한 이벤트에도 '반응'할 수 있음

</br>

* 이벤트 위임: 똑똑하게 일 처리하기
    * 이벤트 버블링을 활용하면, 여러 자식 요소에 각각 이벤트를 달 필요 없이, 부모 요소에 이벤트 핸들러를 단 하나만 등록하여 모든 자식의 이벤트를 처리할 수 있음
    * 이것을 '이벤트 위임'이라고 하며, 코드가 훨씬 효율적이고 유연해짐.
    * 이벤트 위임의 가장 큰 장점은, 나중에 동적으로 추가되는 자식 요소에도 이벤트 핸들러가 자동으로 동작함.

</br>

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>이벤트 전파와 위임</title>
    <style>
        ul { background: lightgray; padding: 20px; }
        li { background: lightblue; margin: 10px; }
        .highlight { font-weight: bolder; text-decoration: underline; color: crimson; }
    </style>
</head>
<body>
<h1>이벤트 전파(Propagation)와 위임(Delegation)</h1>

<hr>

<h3>1. 이벤트 버블링: 연못의 파문처럼!</h3>
<pre>
    하위 요소에서 발생한 이벤트는, 그 파문이 부모 요소를 따라 최상위까지 올라가는 '버블링' 현상을 일으킵니다.
    따라서 부모 요소에 달아둔 이벤트 리스너는, 자식 요소에서 발생한 이벤트에도 '반응'할 수 있습니다.
    </pre>

<ul id="parent"> 부모 (ul)
    <li id="child"> 자식 (li) </li>
</ul>

<script>
   const $parent = document.getElementById('parent');
   const $child = document.getElementById('child');

   $parent.addEventListener('click', (e) => {
        alert('부모가 클릭을 감지했습니다.')
        console.log('부모 핸들러');

        // 이벤트가 최초로 발생한 지점
        console.log('e.target: ', e.target);

        // 이벤트 리스너가 부착된 요소
        console.log('e.currentTarget: ', e.currentTarget);
   })

   $child.addEventListener('click', (e) => {
        alert('자식(li)이 클릭되었습니다.');
   });
</script>

<hr>

<h3>2. 이벤트 위임: 똑똑하게 일 처리하기</h3>
<pre>
    이벤트 버블링을 활용하면, 여러 자식 요소에 각각 이벤트를 달 필요 없이,
    부모 요소에 이벤트 핸들러를 단 하나만 등록하여 모든 자식의 이벤트를 처리할 수 있습니다.
    이것을 '이벤트 위임'이라고 하며, 코드가 훨씬 효율적이고 유연해집니다.
    </pre>

<ul id="drink-list">
    <li>커피</li>
    <li>콜라</li>
    <li>우유</li>
</ul>
<button id="add-btn">음료 추가</button>

<script>
   const $drinkList = document.getElementById('drink-list');
   const $addBtn = document.getElementById('add-btn');

   function highlight(element) {
        element.classList.toggle('highlight');
   }

   // 이벤트 위임 적용
   // 각 li가 아닌, 부모인 ul에 이벤트 핸들러 딱 한번 등록
   $drinkList.addEventListener('click', (e) => {
        console.log('클릭된 요소(e.target):', e.target);

        if (e.target.matches('li')) {
            highlight(e.target);
        }
   });

   // 이벤트 위임의 가장 큰 장점은
   // 나중에 동적으로 추가되는 자식 요소에도 이벤트 핸들러가 자동으로 동작한다.
   $addBtn.addEventListener('click', () => {
        const $newLi = document.createElement('li');
        $newLi.textContent = '사이다';
        $drinkList.appendChild($newLi);
   });
</script>
</body>
</html>
```

### 2-4. 이벤트 제어

</br>

* `preventDefault`: 브라우저의 '자동 반응' 멈추기
* `stopPropagation`: 이벤트의 '연쇄 보고(버블링)' 멈추기

</br>

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>이벤트 제어</title>
    <style>
        body { font-family: sans-serif; line-height: 1.6; }
        .form-group { margin-bottom: 10px; }
        .error-message { color: red; font-size: 12px; }
        .modal-background {
            position: fixed; top: 0; left: 0;
            width: 100%; height: 100%;
            background-color: rgba(0, 0, 0, 0.5);
            display: flex; align-items: center; justify-content: center;
        }
        .modal-content {
            background-color: white;
            padding: 20px;
            border-radius: 8px;
            width: 300px;
        }
    </style>
</head>
<body>
<h1>이벤트 제어: preventDefault와 stopPropagation</h1>

<hr>

<h3>1. `preventDefault`: 브라우저의 '자동 반응' 멈추기</h3>
<pre>
    폼(form)을 제출하면 페이지가 새로고침되는 것이 브라우저의 '기본 동작'입니다.
    `preventDefault`를 사용하면, 이 기본 동작을 막고 우리가 원하는 작업을 먼저 수행할 수 있습니다.
    (예: 사용자가 입력한 값의 유효성 검사)
    </pre>

<form id="login-form">
    <div class="form-group">
        <label for="username">아이디:</label>
        <input type="text" id="username">
    </div>
    <button type="submit">로그인</button>
    <p class="error-message"></p>
</form>


<script>
    const $loginForm = document.getElementById('login-form');
    const $usernameInput = document.getElementById('username');
    const $errorMessage = document.querySelector('.error-message');

    $loginForm.addEventListener('submit', (e) => {
        // '자동 새로고침' 기본 동작 멈추기
        e.preventDefault();
        console.log('자동 새로고침을 막았습니다.');

        // 유효성 검사 수행
        if ($usernameInput.value.trim() === '') {
            $errorMessage.textContent = '아이디를 입력해주세요!';
        } else {
            $errorMessage.textContent = ''
            console.log(`서버로 제출할 아이디: ${$usernameInput.value}`);
            // 여기에 실제 서버로 데이터를 보내는 코드 삽입
            alert('로그인 성공!');
        }
    })

</script>

<hr>

<h3>2. `stopPropagation`: 이벤트의 '연쇄 보고(버블링)' 멈추기</h3>
<pre>
    모달 창의 회색 배경을 클릭하면 창이 닫혀야 합니다.
    하지만 모달 창의 흰색 내용 부분을 클릭했을 때는 닫히면 안 되겠죠?
    이때 'stopPropagation'을 사용해, 이벤트가 부모(회색 배경)로 전파되는 것을 막습니다.
    </pre>

<div id="modal-background" class="modal-background">
    <div id="modal-content" class="modal-content">
        <h3>모달 창</h3>
        <p>이 흰색 영역을 클릭해도 모달은 닫히지 않아야 합니다.</p>
        <p>하지만 바깥 회색 영역을 클릭하면 닫힙니다.</p>
    </div>
</div>

<script>
    const $modalBg = document.getElementById('modal-background');
    const $modalContent = document.getElementById('modal-content');

    $modalBg.addEventListener('click', () => {
        console.log('배경 클릭됨 -> 모달을 닫습니다.');
        $modalBg.style.display = 'none';
    });

    $modalContent.addEventListener('click', (e) => {
        // 이벤트 버블링을 멈춘다!!
        e.stopPropagation();
        console.log('흰색 자식 클릭됨 -> 버블링을 막아 부모에게 가지 않는다.');

        // 내용 부분 클릭했을 때만 수행할 다른 작업을 여기에 추가할 수 있다.
    });
</script>
</body>
</html>
```

### 2-5. 마우스와 키보드 이벤트

* **마우스 이벤트**
    * `click`(클릭) : 마우스 왼쪽 버튼을 눌렀다 뗐을 때 발생
    * `dblclick`(더블클릭)
    * `mousedown`(누를때) : 마우스 버튼을 누르는 순간 발생
        * `e.button` -> 0: 왼쪽, 1: 가운데(휠), 2: 오른쪽
    * `mouseup`(뗄때)
    * `mousemove`(움직일때)
    *  `contextmenu`: 마우스 오른쪽 버튼을 눌렀을 때
    * 등등...


</br>

* **키보드 이벤트**
    * `keydown`: 키를 누르는 순간 (누르고 있는 동안 계속 발생)
    * `keyup`: 키에서 손을 떼는 순간
    * `event.key`: 입력된 문자를 알려줌 (ex: 'a', 'A', 'Enter')

```html
   const $username = $form.username;
   //const $username = document.querySelector('[name="username"]');
   const $hobbies = $form.hobby;    // name이 같은 요소들은 컬렉션(NodeList)으로 가져옴.
   const $introduce = $form.introduce;
   const $counter = document.getElementById('char-counter');
   const $error = document.querySelector('.error');

   // 폼 요소 이벤트 활용
   // focus & blur : 요소에 포커스가 가거나 벗어났을 때

   $username.addEventListener('blur', (e) => e.target.classList.remove('focused'));

            return;

        $error.textContent = '';
        alert('회원가입 성공! 서버로 제출합니다.');

   });

</script>
```

## 3. Timer

### 3-1. 비동기 프로그래밍

</br>

* JS는  싱글 스레드 언어
* 동기 처리 시 블로킹(Blocking) 문제
* 멀티 스레드인 브라우저에 맡겨 비동기 처리 진행

</br>

<대표적인 비동기 함수>

* `setTimeout` : 1회성 예약
* `clearTimeout` : 예약 취소 가능
* `setInterval` : 반복 실행
* `clearInterval` : 반복 실행 취소


</br>


```html
<body>
<h1>비동기(Asynchronous) 프로그래밍</h1>
<hr>
<h3>1. '동기' 식당의 문제점: 블로킹(Blocking)</h3>
<pre>
    '동기' 처리는 앞선 작업이 끝날 때까지 다음 작업이 하염없이 기다리는 방식입니다.
    웹 페이지에서 시간이 오래 걸리는 작업을 동기 방식으로 처리하면, 페이지 전체가 '얼음'처럼 멈춰버립니다.
    </pre>
<button id="sync-btn">동기 작업 시작 (3초 멈춤!)</button>
<button id="test-btn">반응 테스트</button>
<script>
    function sleep(delay) {
        const delayUntil = Date.now() + delay;
        while(Date.now() < delayUntil);
    }

    document.getElementById('sync-btn').addEventListener('click', () => {
        console.log('동기 작업 시작......');
        sleep(3000);    // 이 함수가 실행되는 3초 동안은 멈춤
        console.log('동기 작업 완료!');
    })
</script>

<hr>

<h3>2. '비동기' 식당의 해결책: 타이머 함수</h3>
<pre>
    `setTimeout`과 `setInterval`은 대표적인 비동기 함수입니다.
    '나중에 할 일'을 브라우저에게 맡겨두고, 자신은 즉시 다음 코드를 실행하여 멈춤 현상을 막습니다.
    </pre>

<h4>setTimeout: "조금 이따가, 딱 한 번만 해줘!"</h4>
<script>
   const timerId = setTimeout(() => {
    console.log('3초가 지났습니다.');
   }, 3000);

   console.log('타이머는 예약되었습니다.');

   // clearTimeout(timerId);   // 예약을 취소할 수도 있다.
</script>

<h4>setInterval: "계속 반복해서 해줘!" (feat. clearInterval)</h4>
<script>
   let count = 1;
   const intervalId = setInterval(() => {
        console.log(`${count}초`);
        
        // 5초가 되면 반복을 멈춥니다.
        if(count++ === 5) {
            clearInterval(intervalId);
            console.log('반복이 중지되었습니다.');
        }
   }, 1000);
</script>

<hr>

<h3>3. 비동기는 어떻게 동작할까? (이벤트 루프)</h3>
<pre>
    자바스크립트는 한 번에 한 가지 일만 할 수 있는 '싱글 스레드'입니다.
    하지만 브라우저는 타이머, 네트워크 요청 등 여러 일을 동시에 할 수 있는 '멀티 스레드'이죠.

    1. 호출 스택(Call Stack): 코드가 실행되는 작업 공간입니다.
    2. Web API: setTimeout 같은 오래 걸리는 작업은 브라우저에 맡겨 처리합니다.
    3. 태스크 큐 (Task Queue): Web API에서 끝난 작업(콜백 함수)이 순서대로 대기하는 줄입니다.
    4. 이벤트 루프 (Event Loop): Call Stack이 비었을 때, Task Queue의 작업을 Call Stack으로 옮겨 실행시킵니다.
    </pre>
<script>
    console.log('Event Loop: 시작!');
    setTimeout(() => console.log('Event Loop: 0초 타이머 완료!'), 0);
    console.log('Event Loop: 끝!');
</script>
</body>
```

## 4. BOM(Browser Object Model)

### 4-1. 브라우저 제어 (BOM)

</br>

* `window`는 전역 객체이므로 생략 가능 (예: `alert()`는 사실 `window.alert()`)

</br>

* **사용자와 대화하기**
    * `alert`: 사용자에게 간단한 메시지를 보여주기
    *  `confirm`: 확인/취소 질문. boolean 값 반환(true/false)
    * `prompt`: 사용자에게 텍스트를 입력받음. 입력된 문자열 또는 null 반환

</br>

* **페이지 제어하기**
: `location` 객체는 현재 페이지의 주소(URL) 정보를 담고 있으며, 다른 페이지로 이동(redirect) 시키거나 새로고침할 때 사용됨.
    * `location.href` : 해당 페이지로 이동
    * `location.replace()` : 현재 페이지를 새 페이지로 대체하여 방문 기록에 남지 않음(뒤로 가기 불가)
    * `location.reload()` : 현재 페이지를 새로고침

</br>

* **방문 기록 제어하기**
: `history` 객체로 브라우저의 '뒤로가기', '앞으로가기' 버튼 기능을 흉내 낼 수 있음
    * `history.back()` : 뒤로 가기
    * `history.forward()` : 앞으로 가기
    * `history.go(-2)` : 2페이지 뒤로 가기

</br>

* **브라우저/화면 정보 얻기 (참고용)**
: `navigator`와 `screen` 객체를 통해 사용자의 브라우저 종류, 운영체제, 화면 크기 등의 정보를 얻을 수 있음 (주로 통계 수집이나 반응형 처리의 보조 수단으로 사용)
    * `console.log(navigator);`
    * `console.log(screen);`

</br>
