## 3. hooks
### 3-2. useMemo
#### 3-2-1. value

</br>

* 컴포넌트 내부에 시간이나 리소스를 많이 소모하는 연산과 적게 소모하는 연산들
이 있을 때 state가 바뀌는 등의 update 과정으로 **리렌더링이 발생하면 모든 연산
이 실행되고 불필요한 작업으로 인한 성능 저하가 더 가중된다.**

</br>

* **useMemo** hook를 활용하면 **캐싱(useMemo의 첫번째 인자에서 반환한 값)을
통해 불필요 작업이 리렌더링 시에 발생하지 않도록 처리할 수 있다.** 또한 useEffect처럼 의존성 배열에 지정한 값의 변화 시에만 캐싱 된 값이 재할당 되도
록 진행 하여 코드의 성능 및 효율 향상에 도움을 줄 수 있다.


</br>

* **useMemeo함수의 구조**
```
const 변수명= useMemo(() => {
 return useMemo로 캐싱 할 객체
}, [useMemo가 리턴하는 객를 재할당 할 조건이 될 값]);
```


</br></br>

```js
<body>
    <div id="root"></div>

    <script type="text/babel">

        const { useState, useEffect, useMemo }  = React;

        const hardCalculator = (num) => {
            console.log('어려운 계산 시작');
            for(let i = 0; i < 10999999900; i++) {}
            return num + 10000;
        }

        const easyCalculator = (num) => {
            console.log('쉬운 계산 시작');
            return num + 1;
        }

        function App() {

            const [hardNumber, setHardNumber] = useState(1);
            const [easyNumber, setEasyNumber] = useState(1);

            const hardSum = useMemo(() => {
                return hardCalculator(hardNumber);
            }, [hardNumber]);   // hardNumber가 바뀔 때만 이 함수를 다시 실행

            // const hardSum = hardCalculator(hardNumber);
            const easySum = easyCalculator(easyNumber);

            return (
                <>
                    <h3>어려운 계산기</h3>
                    <input 
                        type="number"
                        value={hardNumber}
                        onChange={e => setHardNumber(parseInt(e.target.value))}
                    />
                    <span> + 10000 = {hardSum}</span>
                    <hr/>
                    <h3>쉬운 계산기</h3>
                    <input 
                        type="number"
                        value={easyNumber}
                        onChange={e => setEasyNumber(parseInt(e.target.value))}
                    />
                    <span> + 1 = {easySum}</span>
                </>
            )
        }


        ReactDOM.createRoot(document.getElementById('root')).render(<App />);

    </script>
</body>
```

#### 3-2-2. reference

</br>

*  useEffect의 **의존성 배열로 전달 된 값이 객체**이고 **지역변수로 객체가 선언**되어 있다면 컴포넌트가 **update 되는 시점에 해당 객체는 항상 매번 새로 재할당** 된다.

</br>

* 객체는 재할당 될 때마다 객체의 주소값이 바뀌게 되고 useEffect는 해당 객체가
관리하는 값의 변화에 의해 동작하고 싶지만 컴포넌트가 해당 객체와 상관 없이
update 되는 다양한 경우에 의해서도 재할당 되며 변화로 간주되어 useEffect가
계속 실행되게 된다.

</br>

* 따라서 이를 방지하기 위해서는 useEffect의 **의존성 배열에 등록 할 객체를
useMemo로 캐싱**하여 이 객체가 아닌 다른 이유로 컴포넌트가 update 되어 리렌
더링 될 경우 useMemo를 의존성 배열로 가지는 useEffect는 동작하지 않게 할
수 있다.


</br>

```js
<body>
    <div id="root"></div>

    <script type="text/babel">

        const { useState, useEffect, useMemo } = React;

        function App() {

            const [isKorea, setIsKorea] = useState(true);
            const [number, setNumber] = useState(0);

            console.log('렌더링...');

            const location = useMemo(() => {
                return { country: isKorea ? '한국' : '외국'}
            }, [isKorea]); // isKorea 값이 바뀔 때만 새로운 객체를 만들어 줘

            // const location = {
            // country: isKorea ? '한국' : '외국'
            // };

            useEffect(() =>{
                console.log('useEffect 호출됨... location이 변경되었습니다.');
            }, [location]); // location 객체가 바뀔 때마다 실행

            return (
                <>
                    <h2>지금 당신이 있는 위치는?</h2>
                    <p>국가: {location.country}</p>
                    <button onClick={() => setIsKorea(!isKorea)}>국가 토글 하기</button>
                    <hr/>
                    <h2>좋아하는 숫자를 입력해 주세요</h2>
                    <input 
                        type="number"
                        value={number}
                        onChange={e => setNumber(e.target.value)}
                    />
                </>
            );
        }
       
        ReactDOM.createRoot(document.getElementById('root')).render(<App />);

    </script>
</body>
```

### 3-3. useCallback
#### 3-3-1. function-memorization

</br>

* 컴포넌트가 update 될 때마다 **컴포넌트 내부에 지역변수로 선언한 함수가 있다면,** 해당 함수는 매번 불필요하게 새로 생성된다.

</br>

* 만약 이 함수가 useEffect의 의존성 배열에서 사용된다면 **함수와 관련 없는 이유로 컴포넌트가 리렌더링 될 때도 함수가 다시 정의** 되며(함수도 객체의 일종으로 재할당 되어 주소값이 바뀜) useEffect가 매번 동작하게 된다.

</br>

* 함수 재할당이 불필요하게 계속 되어 리렌더링 시 변화로 간주될 때  **useCallback을 이용하여 해당 함수를 캐싱(memoization)** 할 수 있다.

</br>

* 캐싱되는 값은 useCallback의 첫번째 인자로 작성 된 익명함수이다.
* 또한 useCallback의 의존성 배열을 사용하여 의존성 배열에 등록된 값의 변화가
생길 때만 함수가 재할당 되도록 할 수도 있다.

</br>

* **useCallback함수의 구조**
```
const 변수명= useCallback(useCallback으로 캐싱 할 함수,
 [useCallback의 함수를 재할당 하게할 값]);
```
</br>

* **useMemo vs useCallback**
    * 의존성 배열에 등록된 것이 **리터럴 객체**이고 재할당 되는 문제 때문에 **useMemo**를 쓴다.
    * 반면에 의존성 배열에 등록된 것이 **함수**이고 함수의 재할당으로 문제가 된다면 **useCallback**을 사용하면 된다.



</br>

```js
<body>
    <div id="root"></div>

    <script type="text/babel">

        const { useState, useEffect, useCallback } = React;

        function App () {

            const [number, setNumber] = useState(0);
            const [toggle, setToggle] = useState(false);

            const printNumber = useCallback(() => {
                console.log('current number: ', number);
            }, [number]); // number 값이 바뀔 때만 이 함수를 새로 만들어라
            // 함수 안에서 사용하는 state나 props가 있다면, 반드시 의존성 배열에 넣어줘야 한다.

            // const printNumber = () => {
            //     console.log('current number: ', number);
            // };

            useEffect(() => {
                console.log('printNumber 함수가 변경 되었습니다.');
            }, [printNumber])

            return (
                <>
                    <input 
                        type="number"
                        value={number}
                        onChange={e => setNumber(parseInt(e.target.value))}
                    />
                    <button onClick={printNumber}>숫자 출력</button>
                    <hr/>
                    <button onClick={() => setToggle(!toggle)}>토글 버튼</button>
                    <p>토글 상태: {String(toggle)}</p>  {/*불린값은 문자열로 바꿔야 JSX 문법으로 화면에 표현된다. */}
                </>
            );
        }

        ReactDOM.createRoot(document.getElementById('root')).render(<App />);
    </script>
    
</body>
```

#### 3-3-2. composited-component

</br>

* 부모 컴포넌트와 자식 컴포넌트가 존재할 때 부모가 준 **props에 변화가 있을 때와
없을 때** 자손 컴포넌트에 있는 **useEffect의 동작 여부를 구분하여 적용**할 수 있다.


</br>

```js
<body>
    <div id="root"></div>

    <script type="text/babel">

        const { useState, useEffect, useCallback } = React;

        function Square({genSquareStyle}) {
            console.log('자식 컴포넌트(Square) 렌더링');

            // 부모가 준 스타일을 저장할 state
            const [style, setStyle] = useState({});

            useEffect(() => {
                console.log('자식 useEffect 실행(스타일 변경됨)');
                setStyle(genSquareStyle());
            }, [genSquareStyle])

            return <div style={style}></div>;
        }

        function App () {

            const [size, setSize] = useState(200);
            const [isDark, setIsDark] = useState(false);

            const genSquareStyle = useCallback(() => {
                return {
                    backgroundColor: 'orangered',
                    width: `${size}px`,
                    height: `${size}px`
                };
            }, [size])

            // size state를 이용해 스타일 객체를 만드는 함수 정의
            // const genSquareStyle = () => {
            //     return {
            //         backgroundColor: 'orangered',
            //         width: `${size}px`,
            //         height: `${size}px`
            //     };
            // };

            return (
                <>
                    <div style={{backgroundColor: isDark? 'black' : 'white'}}>
                        <input 
                            type="range" min="100" max="300"
                            onChange={e => setSize(parseInt(e.target.value))}
                        />
                        <button onClick={() => setIsDark(!isDark)}>테마 변경</button>
                        <Square genSquareStyle={genSquareStyle} />
                    </div>
                </>
            );
        }

        ReactDOM.createRoot(document.getElementById('root')).render(<App />);
    </script>
</body>
```

### 3-4. useRef
#### 3-4-1. rendering-problem

</br>

* useRef도 useMemo나 useCallback처럼 리렌더링에 지정 받지 않도록 따로 캐
싱해 저장하는 개념이다. **(변수 관리)**
* 일반적으로는 DOM 요소를 저장해 놓고 다시 참조하기 위해 **DOM 요소를 캐싱**하는 개념으로 사용한다.(특정 **DOM 요소를 선택**하는 선택자와 같은 개념)

</br>

* **state는 리렌더링 시에 초기 값으로 다시 초기화** 된다.
* state 변화로 인한 리렌더링 시 컴포넌트의 지역변수 초기화와 같은 컴포넌트 내부의 많
은 요소들이 지장을 받을 수 있다.

</br>

* useRef를 사용하여 **원하는 값을 리렌더링에 의해 지장 받지 않고 사용**할 수 있다.
* **useRef의 속성 current**: useRef의 인자로 전달한 초기 값을 담고 있으며 수정이
가능하다. (DOM 요소의 ref attribute를 통해 선언한 useRef가 DOM 요소를 저장하고 리렌더링에 의해 영향을 받지 않도록 할 수 있다.)

</br></br>

* **useRef 속성**
state 변화를 통해 리렌더링이 발생했을 때
1. **useRef에 저장한 값**의 변화는 계속 유지된다.
2. **리터럴 값을 지닌 지역 변수**는 리렌더링 시 초기화 된다.
3. **useRef에 담긴 값**은 리렌더링 시 화면에 반영 되지만 지역 변수의 값은 반영되
지 않는다.



</br></br>

```js
<body>
    <div id="root"></div>

    <script type="text/babel">

        const { useState, useRef, useEffect } = React;

        function Counter() {

            console.log('Counter 렌더링');

            // 1. useState (값이 바뀌면 컴포넌트를 '리렌더링')
            const [count, setCount] = useState(0);

            // 2. 일반 지역 변수
            let variable = 0;

            // 3. useRef : .current 프로퍼티에 값 저장
            const countRef = useRef(0);

            const increaseCount = () => {
                setCount(count + 1);
            };

            const increaseVariable = () => {
                variable += 1;
                console.log('지역 변수 값: ', variable);
            };

            const increaseCountRef = () => {
                countRef.current += 1;
                console.log('Ref 값: ' , countRef.current);
            };

            return (
                <>
                    <h1>State: {count}</h1>
                    <h2>Variable: {variable}</h2>
                    <h3>Ref: {countRef.current}</h3>
                    <button onClick={increaseCount}>State 증가</button>
                    <button onClick={increaseVariable}>Variable 증가</button>
                    <button onClick={increaseCountRef}>Ref 증가</button>
                </>
            );
        }

        function App () {
            return (
                <>
                    <Counter />
                </>
            )
        }

        ReactDOM.createRoot(document.getElementById('root')).render(<App />);
    </script>
</body>
```
</br></br>

#### 3-4-5. input-ref

</br>

* useRef는 **DOM 요소를 저장할 목적으로도 사용**한다.
* useRef에 저장할 DOM 요소에는 ref 어트리뷰트를 주고 사용하는 useRef함수명
을 작성하면 useRef는 DOM 요소를 저장하게 되고 리렌더링 되더라도 DOM 요소를 저장해 기억하고 있을 수 있다.


</br>

```js
<body>
    <div id="root"></div>

    <script type="text/babel">

        const { useState, useEffect, useRef } =  React;


        function App () {

            const [form, setForm] = useState({
                username: '',
                password: ''
            });

            // useRef로 서랍을 만든다.
            const usernameRef = useRef();

            useEffect(() => {
                console.log('마운트 되었습니다.');
                console.log(usernameRef.current);
                usernameRef.current.focus();
            }, []);

            const onChangeHandler = (e) => {
                setForm({
                    ...form,
                    [e.target.name]: e.target.value
                });
            };

            const onClickHandler = () => {
                alert(`username: ${form.username}, password: ${form.password}`);
                setForm({ username: '', password: ''});
                // 로그인 버튼 클릭 후에도 다시 username 포커스
                usernameRef.current.focus();
            };

            return (
                <>
                    <input 
                        type="text"
                        name="username"
                        onChange={onChangeHandler}
                        value={form.username}
                        ref={usernameRef}
                    />
                    <br/>
                    <input 
                        type="password"
                        name="password"
                        onChange={onChangeHandler}
                        value={form.password}
                    />
                    <br/>
                    <button onClick={onClickHandler}>로그인</button>
                </>
            );
        }

        ReactDOM.createRoot(document.getElementById('root')).render(<App />);
    </script>
    
</body>
```

### 3-5. custom hook
#### 3-5-1. custom hook

</br>

* 코드에서 **반복되는 코드들이 존재한다면 하나의 개념으로 묶어 관리**할 수 있다. 

</br>

* input 태그에 입력 받은 값을 state로 관리하는 이유
1. **사용자가 입력한 값**을 선택자 없이 읽어오기 위함
2. react는 **form 태그를 쓰지 않는다**.
(state의 값을 **비동기 방식 통신을 하여 다른 곳으로 전송**하게 된다.)

</br>

```js
<body>
    <div id="root"></div>

    <script type="text/babel">

        const { useState, useEffect } = React;

        // 커스텀 훅 정의
        // 이름이 'use'로 시작하는 일반 자바스크립트 함수
        // 내부에서 useState와 useEffect를 마음껏 사용할 수 있다.
        function useDelayTimer(delay) {
            // 시간이 지났는지 여부를 저장하는 상태
            const [isReady, setIsReady] = useState(false);

            useEffect(() => {
                console.log(`${delay}ms 타이머 시작!`);

                const timer = setTimeout(() => {
                    setIsReady(true);
                    console.log('타이머 종료! 준비 완료');
                }, delay);

                // 언마운트 될 때 타이머 정리(메모리 누수 방지)
                return () => clearTimeout(timer);
            }, [delay]);

            return isReady; 
        }

        function App () {

            const isReady = useDelayTimer(3000);

            return (
                <>
                    <h1>Custom Hook</h1>
                    <hr/>
                    { isReady ? 
                        <h2 style={{color: 'blue'}}>준비 완료!! 안녕하세요~</h2>
                        : <h2 style={{color: 'red'}}>잠시만 기다려주세요...</h2>
                    }
                </>
            );
        }

        ReactDOM.createRoot(document.getElementById('root')).render(<App />);
    </script>
    
</body>
```

## 4. Async
### 4-1. Intro
#### 4-1-1. callback-hell

</br>

💡 **비동기(async)-넌블로킹(nonblocking) 작업**
* 메인 흐름은 멈추지 않는 상태에서 특정 작업들을 백그라운드에서 처리하여 **동시에 처리하는 것처럼 실행**함
* 비동기 작업을 할 때 **가장 많이 사용하는 방식이 콜백 함수를 이용하는 방식**이다.

</br>

* 비동기 처리를 위해 콜백 함수를 이용하다 보면 특정 **비동기 처리 이후 수행 할 내용을 또 정의**해야 하는 경우 **콜백 함수의 중첩**이 생기고 이러한 것이 많이 추가되면 **콜백 지옥**이 펼쳐진다.

</br>

```js
<body>
    <h1>콘솔 확인!</h1>

    <script>

        function sayHello() {
            console.log('3초 뒤에 음식이 나왔습니다.');
        };

        console.log('햄버거를 주문합니다.');
        setTimeout(sayHello, 3000);
        console.log('감자튀김을 주문합니다.');

        function increase(number, callback) {
            setTimeout(() => {
                const result = number + 10;
                console.log(result);
                if (callback) {
                    callback(result);
                }
            }, 1000);
        }

        console.log('작업 시작..');
        // 0부터 시작해서 10씩 3번 더하는 작업을 순차적으로 실행하고 싶을 때...
        increase(0, (result) => {
            increase(result, (result) => {
                increase(result, (result) => {
                    console.log('모든 작업이 끝났습니다.');
                });
            });
        });
    </script>
</body>
```

</br></br>


#### 4-1-2. promise

</br>

💡 **promise**
:  콜백 지옥과 같은 코드가 형성되지 않게(비동기 통신 간에 순서를 정하기 쉽게) 하는 방안으로 ES6에서 도입

* 비동기 연산이 종료 된 이후의 결과 값과 실패 사유를 처리하기 위한 처리기를 연
결할 수 있음
* **최종 결과를 반환하는 것이 아닌 미래의 어떤 시점에 결과를 제공하겠다는 ‘약속’을 반환**함

</br>

**<promise의 상태>**
* 대기(pending): 이행하지도, 거부하지도 않은 초기 상태
* 이행(fulfilled): 연산이 성공적으로 완료된 상태
* 거부(rejected): 연산이 실패한 상태

</br>

* promise 객체는 resolve와 reject 함수를 활용한다.
1. **resolve**: 함수의 인자로 넘어온 값을 저장하고 있다가 then을 만나면 저장했던
값을 지닌 Promise 객체를 반환한다.
2. **reject**: 어떠한 이유로 거부되어야 할(조건일) 때의 Promise 객체를 반환한다.



</br>

```js
<body>
    <h1>콘솔 확인!</h1>

    <script>

        /*
        - Promise
        비동기 작업이 미래의 언젠가 끝날 텐데, 
        작업이 끝나면 성공(resolve)했는지 실패(reject)했는지 꼭 알려줄게!
        라고 약속하는 '약속 증서' 객체를 먼저 반환하는 개념이다.
        */

        function increase(number) {
            const promise = new Promise((resolve, reject) => {
                setTimeout(() => {
                    const result = number + 10;

                    if(result > 50) {
                        // 실패 -> reject 함수 호출하며 에러 전달
                        const e = new Error('숫자가 너무 큽니다!');
                        return reject(e);
                    }
                    // 성공 -> 계산된 결과와 함께 resolve 처리
                    resolve(result);
                }, 1000);
            });
            return promise;
        }

        increase(0)
            .then(number => {   // increase가 성공하면 그 결과(number)를 받아서 실행
                console.log(number);
                return increase(number);
            })
            .then(number => {
                console.log(number);
                return increase(number);
            })
            .then(number => {
                console.log(number);
                return increase(number);
            })
            .then(number => {
                console.log(number);
                return increase(number);
            })
            .then(number => { 
                console.log(number);
                return increase(number);
            })
            .catch(error => {   //.then() 체인 중간에 reject 하면 여기서 잡힘
                console.error(error);
            })
            .finally(() => {    // 성공하든 실패하든 상관없이 무조건 마지막에 실행
                console.log('모든 작업이 끝났습니다.');
            })

    </script>
</body>
```

#### 4-1-3. async-await

</br>

💡 promise 객체를 더 쉽게 사용할 수 있도록 asynch/await가 ES2017(ES8)에서
추가 되었다.

* **await 키워드를 사용**해서 **promise를 반환하는 함수를 호출**하면 해당 **promise의 resolve에 저장된 값이 반환** 되게 된다.

* then을 사용하지 않고(메소드 체이닝 방식 없이) **비동기 처리 함수를 동기식으로 처리**할 수 있다.

</br>

```js
<body>
    <h1>콘솔 확인!</h1>

    <script>
        function increase(number) {
            const promise = new Promise((resolve, reject) => {
                setTimeout(() => {
                    const result = number + 10;

                    if(result > 50) {
                        // 실패 -> reject 함수 호출하며 에러 전달
                        const e = new Error('숫자가 너무 큽니다!');
                        return reject(e);
                    }
                    // 성공 -> 계산된 결과와 함께 resolve 처리
                    resolve(result);
                }, 1000);
            });
            return promise;
        }

        async function run() {
            console.log('작업시작...');
            // await: increase(0) Promise가 끝날 때까지 기다렸다가,
            //        resolve된 결과값을 result 변수에 할당

            try {
                let result = await increase(0);
                console.log(result);
    
                result = await increase(result);
                console.log(result);
    
                result = await increase(result);
                console.log(result);
    
                result = await increase(result);
                console.log(result);
    
                result = await increase(result);
                console.log(result);
    
                result = await increase(result);
                console.log(result);

            } catch (error) {   // try 블록 안에서 reject 되면 catch 블록 실행
                console.error(error);
            }
            console.log('모든 작업이 끝났습니다.');
        }

        run();

    </script>
</body>
```
