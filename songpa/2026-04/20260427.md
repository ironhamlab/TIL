#### 🌟리액트쿼리 사용법 정리
: 데이터를 가져오거나 보내는 행위(네트워크 통신)는 여전히 fetch나 axios가 담당함. 리액트쿼리는 그 fetch를 감싸서 "상태관리(로딩, 에러, 캐싱)"를 대신해주는 매니저 역할이라고 보면 됨.

</br>

**※ fetch로 하던 일을 리액트쿼리로 바꿀 때**
|기존방식(수동)|리액트쿼리(자동화)|사용도구|
|------|---|---|
|데이터 조회, 데이터를 가져올 때(GET)|데이터를 조회하고 기억(캐싱)함|`useQuery`|
|서버데이터 수정 및 추가, 데이터를 보낼 때(POST, PUT, DELETE)|데이터를 서버에 전송하고 성공/실패 관리함|`useMutation`|
|데이터가 바뀌었을 때(새로고침)|기존에 저장된 데이터는 낡았으니 새로 가져오라고 시킴|`invalidateQueries`|

* 실제 백엔드라면 서버가 JOIN 쿼리를 날려서 합쳐진 결과를 주면 되지만, 현재는 json-server를 사용하고 있기 때문에 Client-side Join + 캐싱을 사용하게 됨.
* `fetchAllData`로 마스터데이터를 한 번에 호출하여 TanStackQuery 로 전역 캐싱해두면, 이미 메모리에 있는 데이터를 재사용하게 됨!

* **const router  = useRouter();**
-> Next.js에서 제공하는 기능으로, "지금 보고 있는 페이지 주소를 옮기거나 조작할 때" 사용.
    * 주요 역할 : 페이지 이동
        * `router.push('/')` : 홈으로 이동 (새 주소로 보냄)
        * `router.back()` : 뒤로가기 (이전 페이지로 보냄)
        * `router.replace('/')`: 기록을 남기지 말고 홈으로 교체

</br>

* **const queryClient = useQueryClient();**
-> 리액트쿼리(TanStack Query)에서 제공하는 기능으로, **우리 앱이 서버에서 가져와서 보관 중인 데이터 창고**에 접근하는 열쇠.
    * 주요 역할: 데이터 상태(캐시) 관리
        * `queryClient.invalidateQueries({ queryKey: ['prompts']})` : prompt 라는 이름의 데이터 창고를 지금 당장 비워라
