1.  HTTP URL을 비동기요청한다고 실행하는 순간, 서버쪽에서는 이 로직을 담당하는 메서드를 실행해달라는 명령이 내려진다.

* **JVM**: 자바프로그램만을 위해서 존재하는 가상 머신.
    * 자바 사용 시 서버를 안정적으로 돌리는 JVM 필요!

    * 예전에는 브라우저 파편화 문제가 많았는데, 자바는 JVM 때문에 운영체제나 하드웨어 등에 상관없이 코드가 항상 동일하게 작동하도록 보장되는 표준화된 실행환경을 보장함. 

</br>

* 서버에서 메서드가 실행된다면, 자바는 **효율적인 메모리 관리를 위해 스택(Stack)과 힙(Heap)이라는 메모리로 구분**해서 가지고 있음.

</br>

* **Stack 메모리가 관리하는 대상** : 실제 실행 흐름, 메모리 주소를 변수를 통해 참조

* **Heap 공간** : 실제 객체 자체 생성

</br>

* 자바는 **멀티스레드**임. 각 요청마다 별도로 스레드를 할당해서 병렬로 처리를 함. 수많은 트래픽을 감당해내는 방식이 멀티스레드여서 가능함.

## 1. JDK와 JRE (중요)

* **JDK(Java Development Kit)** → 개발자용 풀버전을 설치한다.

* **JRE(Java Runtime Environment)** → 실행만 시킬때는 JRE만 있어도 됨.

</br>

* 자바 컴파일러는 **자바언어를 기계어로 번역, 오타나 문법 오류 등**을 알려줌.
* 자바의 컴파일러는 다른 언어들의 번역기와는 조금 다르게, .java 코드 컴파일 시 자바 만의 중간 언어인 **Byte Code(.class)** 로 번역한다.

* 공용어인 Byte Code를 Window로 가져가면 window용 JVM, MacOS로 가져가면 Mac용 JVM 등, OS에 맞게 **JVM이 알아서 한 번 더 통역**해 각 환경에 맞게 실행됨.




</br>

* **IDE** → 통합 개발 환경.

# Chapter 2. 변수
## 1. 리터럴
### 1-1. 리터럴 개요
### 1-1-1. 리터럴이란?
* **리터럴(literal)** 이란 **변하지 않는 데이터 그 자체**를 말한다. 

* 상수와 혼동할 수 있지만 상수는 데이터가 저장되는 메모리상의 공간을 의미하고, 리터럴은 **고정된 값 자체**를 의미한다.

</br>

### 1-1-2. 리터럴의 종류
: 논리형, 정수형, 실수형, 문자형, 문자열

</br></br>

## 1-2. 리터럴 활용
### 1-2-1. 리터럴 출력
```java
public class Application1 {
    public static void main(String[] args) {

        // 숫자 형태의 값
        /* 정수형태의 값 출력 */
        System.out.println(123);

        /* 실수 형태의 값 출력 */
        System.out.println(1.23);


        /* 문자 형태의 값 */
        // 문자 형태의 값은 홑따옴표로 감싸주어야 한다.
        System.out.println('a');

        // 두 개 이상은 문자로 취급하지 않는다. 에러 발생
//        System.out.println('ab');

        // 아무 문자도 기록되지 않는 경우도 에러 발생
//        System.out.println('');   


        /* 문자열 형태의 값 */
        // 문자 여러 개가 나열된 형태를 말하며, 쌍따옴표로 감싸주어야 한다.
        System.out.println("안녕하세요");
        System.out.println("");

        // 한 개의 문자도 쌍따옴표로 감싸면 문자열이다.(문자 'a'와는 다름)
        System.out.println("a");


        /* 논리 형태의 값 출력 */
        System.out.println(true);
        System.out.println(false);
    }
}
```

</br></br>

### 1-2-2. 숫자 리터럴의 연산
```java
// 정수와 정수의 연산
System.out.println(123 + 456);   // 579
System.out.println(123 - 456);   // -333
System.out.println(123 * 456);   // 56088
System.out.println(123 / 456);   // 0
System.out.println(123 % 456);   // 123

// 실수와 실수의 연산
System.out.println(1.12 + 1.23); // 2.35

// 정수와 실수의 연산 (항상 실수가 나온다)
System.out.println(123 + 0.23);  // 123.23
```

</br>

* 실수와 실수의 연산
    * 실수 연산에서 오차가 생기는 이유는 **실수를 표현하는 방식이 부동소수점 방식이기 때문**이다. 

    * **부동소수점(floating-point)** 이란 **소수점 이하의 위치를 고정하지 않고 가수와 지수로 나타내는 방식의 실수 표현 방식**을 말한다.

    * 이러한 방식은 정확한 실수 표현이 어렵기 때문에, 연산 결과에 약간의 오차가 발생할 수 있다.

</br></br>

### 1-2-3. 문자 리터럴의 연산
```java
// 문자는 내부적으로 숫자 취급을 한다(아스키코드와 유니코드)
System.out.println('a' + 'b');   // 195
```
</br>

* **아스키코드**
    * 어떠한 문자를 어떠한 숫자로 이해할 것인지 약속을 1963년 미국 ANSI에서 표준화한 정보 교환용 7비트 부호체계로 정의한 것을 ASCII(American Standard Code for Information Interchange, 미국 정보 교환 표준 부호) 코드 라고 하며, 0 ~ 127번 까지 문자와 숫자가 매핑되어 있다.

</br>

* **유니코드**
    * 아스키 코드만으로는 전 세계의 언어를 취급할 수 없는 한계점이 존재한다. 이러한 필요에 의해 유니코드라는 것이 정의되었다.
    * 유니코드란 전 세계의 모든 문자를 다루도록 설계된 표준 문자 전산처리 방식이다. 전 세계 모든 문자를 담는 ISO/IEC 10646 코드표를 사용해 각 문자 충돌 문제를 해결했다.
    * 처음에 문자 코드는 ASCII 코드가 대세였는데, 이 코드 1바이트로 문자를 표현하기 때문에 각 국의 문자가 깨지는 문제가 자주 발생하였다. 이에 2~3바이트 공간에 모든 문자를 할당하여 문제를 해결한 것이 유니코드이다.
    * 우리가 자주 보는 UTF-8 인코딩도 유니코드에 기반한 인코딩 방식 중 하나이다.

</br></br>

### 1-2-4. 문자열 리터럴의 연산
```java
// 문자열과 문자열의 '+' 연산 결과는 문자열 합치기가 된다.

// + 연산 외에 다른 연산은 사용하지 못함
// System.out.println("hello" - "world");
```

</br></br>

### 1-2-6. 문자열 이어붙이기
