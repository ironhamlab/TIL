# 01. MyBatis Configuration by JAVA

## 01-01. Environment class

### 01-01-01. Environment란


💡 데이터베이스 접속에 관한 환경 설정 정보를 가진 객체로, MyBatis 환경 설정 객체를 생성하는 데 사용한다.

- MyBatis framework 라이브러리에서 제공하는 클래스이다.

</br></br></br>

### 01-01-02. Environment 객체 생성 방법

```java
Environment environment = new Environment(*환경 정보 이름* , *트랜잭션 매니저 종류* , *커넥션풀 사용 여부*);
```

</br>

- Environment 클래스는 기본 생성자를 제공하지 않는다.
- 객체 생성 시 전달하는 매개변수는 차례로 다음과 같다.

</br>

1. 환경 정보 이름 : 생성할 환경 정보의 이름을 설정한다.
</br>
2. 트랜잭션 매니저 종류는 두 가지가 있고, 안전한 트랜잭션 관리를 위해 JdbcTransactionFactory 사용을 권장한다.
    - JdbcTransactionFactory : 코드 작성을 통해 수동으로 커밋을 조작
    - ManagedTransactionFactory : JDBC가 자동으로 커밋을 수행
    </br>
3. 커넥션풀 사용 여부에 따라 두 가지 설정을 할 수 있고, 사용하는 경우 Connection 속도 및 메모리 효율이 증대되는 장점이 있다.
    - 어떤 설정을 사용하든 생성 시 데이터베이스 연결을 위한 설정 정보(드라이버, 데이터베이스 URL, USER, 비밀번호)를 인자값으로 주어야 한다.
    - PooledDataSource : ConnectionPool 사용
    - UnpooledDataSource : ConnectionPool 사용하지 않음

</br></br></br>

### 01-01-03. Environment class 사용 예시

```java
Environment environment = new Environment("dev", new JdbcTransactionFactory(), new PooledDataSource(DRIVER, URL, USER, PASSWORD));
```

### 01-02-01. Configuration이란

```java

configuration.addMapper(Mapper.class);
```

- addMapper() 메소드는 설정 객체에 매퍼를 등록한다.

## 01-03. SqlSessionFactory와 SqlSession

### 01-03-01. SqlSessionFactory와 SqlSessionFactoryBuilder

```java
SqlSessionFactory sqlSessionFactory = new SqlSessionFactoryBuilder().build(configuration);
```

</br>

1. SqlSessionFactory
    1. SqlSession 객체를 생성하기 위한 팩토리 역할을 수행하는 인터페이스이다.
    2. 애플리케이션이 실행되는 동안 여러 차례 빌드하지 않도록, 싱글톤 패턴 등을 이용하여 어플리케이션 스코프로 사용하는 것이 좋다.
    </br>
2. SqlSessionFactoryBuilder
    1. SqlSessionFactory 인터페이스 타입의 하위 구현 객체를 생성하기 위한 빌드 역할을 수행한다.
    2. build() 메소드는 설정 정보를 담고 있는 Configuration 타입의 객체 혹은 외부 설정 파일과 연결된 스트림을 매개변수로 전달하면 SqlSessionFactory 인터페이스 타입의 객체를 반환한다.
    3. SqlSessionFactoryBuilder 메소드
        
        
        | **method 구분** | **설명** |
        | --- | --- |
        | build(InputStream) | config.xml 파일만 불러옴 |
        | build(InputStream, String)  | config.xml 파일과 지정한 데이터베이스를 불러옴 |
        | build(InputStream, Properties) | config.xml파일과 property 로 설정한 내용으로 불러옴(“${*key*}”) |
        | build(InputStream, String, Properties) | config.xml 파일과 지정한 데이터베이스, properties 파일 불러옴 |
        | build(configuration) | configuration 객체에 설정한 내용을 불러옴 |
        - config.xml은 Resource객체의 getResourceAsStream  메소드를 이용해 InputStream으로 가져온다.
    
</br></br></br></br>

### 01-03-02. SqlSession

```java
SqlSession sqlSession = sqlSessionFactory.openSession(false);
```
</br>

1. SqlSessionFactory의 openSession() 메소드를 사용하여 SqlSession 인터페이스 타입의 객체를 반환받는다.
    
    </br>
2. SqlSession은 멀티 스레드 환경에서 안전하게 사용할 수 없으므로(= Thread-safe 하지 않음), 스레드마다 생성하여 공유되지 않도록 해야 한다. 
    
    따라서 HTTP 요청 라이프사이클과 유사하게, 요청 시 생성하고 요청 처리가 완료되면 close하는 스코프를 권장한다.
    </br>
3. openSession() 메소드
    - boolean 타입을 인자로 전달하는데, 이는 Connection 인터페이스 타입 객체로 DML 수행 후 auto commit 여부에 대한 옵션을 의미한다.
    - auto commit 옵션은 false로 지정하여 트랜잭션을 직접 관리할 수 있도록 하는 것을 권장한다.
    - Mybatis SqlSessionFactory를 통해 Session을 생성하는 openSession() 메소드는 여러가지 형식으로 오버로딩 되어있는데, 그중 대표적인 것은 다음과 같다.
        
        
        | **method 구분** | **설명** |
        | --- | --- |
        | openSession() | 기본값을 통해 SqlSession 생성 |
        | openSession(Boolean) | - SqlSession 생성 시 AutoCommit 여부 지정 - 기본값 = true |
        | openSession(Connection) | - 직접 생성한 Connection 객체를 이용해 SqlSession 생성 - 기본값 = X |
        | openSession(ExecutorType) | - 쿼리 실행 시 PreparedStatement의 재사용여부 설정 - 기본값 = ExecutorType.SIMPLE |
    </br>
4. SqlSession은 사용 후 반드시 close()하여 반납해야 한다.
    
    ```java
    sqlSession.close();
    ```
    </br>
5. mapper.xml에서 선언한 쿼리 구문을 SqlSession에서 실행하는 메소드는 총 6가지로 아래와 같다.
    
    
    | **method명** | **설명** |
    | --- | --- |
    | Object selectOne(String mapper, Object param) | 하나의 객체만을 받을 때 사용 |
    | List<E> selectList(String mapper, Object param) | 결과에 대한 값을 List로 받을 때 사용 |
    | Map<K,V> selectMap(String mapper, Object param, String mapKey) | 결과에 대한 값을 Map으로 받을 때 사용 (마지막 인자로 key로 사용될 컬럼 명시) |
    | int insert(String mapper, Object param) | Database에 데이터를 입력할 때 사용 |
    | int update(String mapper, Object param) | Database의 데이터를 수정할 때 사용 |
    | int delete(String mapper, Object param) | Database의 데이터를 삭제할 때 사용 |

</br></br></br>

# 02. MyBatis Configuration by XML

## 02-01. XML Configuration 파일 구조

### 02-01-01. MyBatis Config XML 파일 작성 방법

(참고) https://mybatis.org/mybatis-3/getting-started.html

1. 설정 정보를 작성하기 위한 mybatis-config.xml 파일을 등록한다.
    
    (설정 파일 경로는 src > main > resources 하위에 폴더를 생성하여 지정하도록 한다.)
</br>    
2. xml 파일 최상단에 다음과 같이 xml 형식을 지정하여 이하의 설정 내용이 mybatis 설정임을 선언한다.
    
    ```xml
    <?xml version="1.0" encoding="UTF-8" ?>
    <!DOCTYPE configuration PUBLIC "-//mybatis.org//DTD Config 3.0//EN" "http://mybatis.org/dtd/mybatis-3-config.dtd">
    ```
    
    - DOCTYPE으로 설정하는 내용은 하위에 사용 가능한 태그, 속성들이 정의되어 있는 파일이다.
        
        → 따라서 해당 파일에 작성하는 태그 혹은 속성 등이 맞게 작성되었는지 확인한다.
        
    </br>
3. 설정 내용 아래 최상위 태그인 `<configuration>`을 작성하고 내부에 필요한 설정을 정보를 작성한다.
    
    ```xml
    <?xml version="1.0" encoding="utf-8"?>
    <!DOCTYPE configuration PUBLIC "-//mybatis.org//DTD Config 3.0//EN" "http://mybatis.org/dtd/mybatis-3-config.dtd">
    <configuration>
    . . .
    </configuration>
    ```
    
</br></br></br></br></br>

## 02-02. MyBatis Configuration XML Tags

### 02-02-01. `<properties>`

1. 설정 파일에서 공통적인 속성을 정의하거나 외부 파일에서 값을 가져오는 태그이다.
2. 외부 프로퍼티 파일은 resource 하위의 경로를 기술하면 된다.
    
    클래스패스 경로가 아닌 경우 url속성에 "file:d:\"로 시작하는 경로를 기술하면 된다.
    
3. `<properties>` 태그 안쪽에 `<property> `태그를 작성하여 properties 파일에 값을 설정할 수 있다.
4. 사용 방법
    - 프로퍼티에 설정된 값을 꺼내올 때는 ${ *key* } 표현식을 사용한다.
    
    ```xml
    <properties resource = “*경로+파일명.properties*”>
    	<property name=“*key명*” value=“*설정값*”>
    </properties>
    ```

 </br></br></br>   

### 02-02-02.` <settings>`

1. SqlSessionFactory 객체가 SqlSession 객체를 만들 때, 생성할 객체의 특성을 설정한다.
2. settings 엘리먼트의 하위 엘리먼트들은 대부분 디폴트값을 가지며, 특별한 경우가 아니면 디폴트값을 사용해도 무방하다.
3. 사용 예시
    
    ```xml
    <settings>
    	<setting name="jdbcTypeForNull" value="NULL"/>
    </settings>
    ```
    
    - 위 속성은 JDBC 타입에 대하여 Null 값이 발생할 경우 빈칸이 아닌 null로 인식하게 한다.
    - 속성 값 참조 사이트 : http://www.mybatis.org/mybatis-3/ko/configuration.html
4. <setting>태그의 하위 엘리먼트는 다음 11가지이다.
    
    
    | 엘리먼트 태그 | 설명 |
    | --- | --- |
    | `<cacheEnabled>` | 캐시 사용 여부 설정 (기본값: true) |
    | `<lazyLodingEnabled>` | 데이터를 필요 시점에 가져와 동작하게 하는 옵션 (성능개선 / 기본값: true) |
    | `<aggressiveLazyLoding>` | 늦은 로딩 활성화/비활성화 옵션 (기본값: true) |
    | `<multipleResultSetEnabled>` |  한 개의 구문에서 여러 개의 결과 셋에 대한 허용여부를 결정하는 옵션 (미지원 드라이버도 있음 / 기본값: true) |
    | `<useColumnLabel>` | 컬럼 이름 대신 컬럼 라벨 사용 여부 설정 (드라이버마다 기본값 다름 / 기본값: true) |
    | `<useGeneratedKeys>` | 생성키 사용 여부를 결정 (기본값: false) |
    | `<autoMappingBehavior>` | 조회 결과 자동 매핑 설정 (기본값: PARTIAL)※ mapper 태그와 동일한 설정이지만, 여기서는 전역 설정을 함 |
    | `<defaultExecutorType>` | - Statement를 재사용하지 않는 설정인 SIMPLE (= 기본값) - PreparedStatement 재사용은 REUSE  - 일괄처리 하는 BATCH |
    | `<defaultStatementTimeout>` | 타임아웃에 대한 양수의 초 단위 전역 설정 (기본값: JDBC 드라이버 자체 설정값) |
    | `<mapUnderscoreToCamelCase>` | DB의 언더바를 이용한 네이밍 규칙과 자바의 낙타봉 표현식을 사용해 자동 매핑할지에 대한 옵션 (기본값: false) |
    | `<localCacheScope>` | - 캐시 저장 범위를 SqlSession으로 할 때 SESSION (= 기본값) - 구문별로 캐시할 때는 STATEMENT를 선택 |

    </br></br></br>

### 02-02-03. `<typeAliases>`

1. MyBatis에서 사용할 자료형의 별칭을 선언한다.
2. 매퍼의 쿼리를 작성할 때 ResultType이나 parameter 속성에 풀클래스명으로 사용해야 하는 클래스의 별칭을 등록하여 간략하게 사용할 수 있다.
3. 사용 예시
    - type 속성에는 풀클래스명을 작성하고, alias 속성에 사용할 별칭을 작성한다.
    
    ```xml
    <typeAliases>
    	<typeAlias type="member.model.vo.Member" alias="Member" />
    </typeAliases>
    ```

### 02-02-04. `<environments>`

1. MyBatis에서 연동할 Database 정보를 등록한다.
</br>

2. `<environments>`태그는 여러 개의 `<environment>`태그를 포함할 수 있으며, default 속성으로 기본 사용할 환경 설정을 지정할 수 있다.
</br>

3. `<environment>`태그 내부에서 사용하는 태그는 다음과 같다.
    1. `<transactionManager>` : 트랜잭션 매니저를 JDBC 혹은 MANAGED로 설정할 수 있다.
        - JDBC : MyBatis API에서 제공하는 commit, rollback 메소드 등을 사용해서 트랜젝션을 관리하는 방식 (수동 commit)
        - MANAGED : MyBatis API 보다는 컨테이너가 직접 트랜젝션을 관리하는 방식 (자동 commit)
    2. `<dataSource>` : 속성으로 커넥션풀 사용 여부를 POOLED와 UNPOOLED로 설정할 수 있다.
        - 설정 가능한 type 중 JNDI도 있는데, 이는 MyBatis에서 Connection 객체를 생성하여 관리하지 않고 Web Application의 설정을 따르겠다는 의미이다.
        - (참고) POOLED 와 UNPOOLED
            - 데이터베이스 연결을 관리하는 DataSource의 타입은 크게 POOLED와 UNPOOLED로 나눌 수 있는데, 그 차이는 다음과 같다.
            
            | 구분 | POOLED | UNPOOLED |
            | --- | --- | --- |
            | 특징 | 최초 Connection 객체 생성 시 해당 정보를 pool 영역에 저장해 두고 이후 Connection 객체를 생성할 때 이를 재사용한다. | Connection 객체를 별도로 저장하지 않고, 호출 시마다 매번 생성하여 사용한다. |
            | 장점  | - Connection 객체를 생성하여 데이터베이스와 연결을 구축하는데 걸리는 시간이 단축된다. | - Connection 연결이 많지 않은 코드를 작성할 때 간단하게 구현할 수 있다. |
            | 단점 | - 단순한 로직을 수행하는 객체를 만들기에는 설정해야 할 정보가 많다. | - 매번 새로운 Connection 객체를 생성하므로 속도가 상대적으로 느리다. |
    3. `<property>` : `<dataSource>`태그 내부에 작성되며, `<properties>`태그를 통해 불러온 파일의 값으로 데이터베이스 정보를 설정한다. 
        - 사용 방법
            
            ```xml
            <dataSource>
            	<property name=“*명칭*” value=“${*properties에 설정된 key명*}” />
            	<property name=“*명칭*” value=“${*properties에 설정된 key명*}” />
            </dataSource>
            ```
</br>

4. 사용 예시
    1. `<properties>`태그를 사용하지 않은 경우
        
        ```xml
        <environments default="development">
        	<environment id="development">
        		<transactionManager type="JDBC" />
        		<dataSource type="POOLED">
        			<property name="driver" value="com.mysql.cj.jdbc.Driver" />
        			<property name="url" value="jdbc:mysql://localhost/menu" />
        			<property name="username" value="sahmyook" />
        			<property name="password" value="sahmyook" />
        		</dataSource>
        	</environment>
        </environments>
        ```
        
    2. `<properties>`태그를 사용한 경우
        
        ```xml
        <properties resource="config/connection-info.properties"/>
        <environments default="dev">
        	<environment id="dev">
        		<transactionManager type="JDBC" />
        		<dataSource type="POOLED">
        			<property name="driver" value="${driver}" />
              <property name="url" value="${url}" />
              <property name="username" value="${username}" />
              <property name="password" value="${password}" />
        		</dataSource>
        	</environment>
        </environments>
        ```
        
</br></br></br>

### 02-02-05. `<mappers>`

1. 사용하고자 하는 쿼리가 정의된 mapper 파일을 등록한다.
</br>

2. 설정하는 방법은 네 가지가 있지만 한 가지 방식으로 통일하여 관리하는 것이 좋다.
    1. `<mapper resource="">` : (상대경로) 클래스패스에 위치한 xml 매퍼 파일 지정
    2. `<mapper url="">` : (절대경로) URL을 사용한 xml 매퍼 파일 지정
    3. `<mapper class="">` : 매퍼 인터페이스를 사용하는 인터페이스 위치 지정
    4. `<package name="">` : 패키지 지정으로 패키지 내 자동으로 매퍼 검색
</br>

3. 사용 예시
    
    ```xml
    <mappers>
    	<mapper resource="member/model/mapper/member-mapper.xml"/>
    	<mapper resource="notice/model/mapper/notice-mapper.xml" />
    	<mapper resource="board/model/mapper/board-mapper.xml" />
    </mappers>
    ```
    
</br></br></br>

### 02-02-06. `<typeHandler>`

1. PreparedStatement에서 파라미터를 설정하거나 결과셋을 가져올 때 테이블 각 컬럼을 자바의 적절한 타입으로 설정해서 가져오기 위해 사용한다.
</br>
2. MyBatis 정의한 타입 핸들러가 있기 때문에 대부분의 경우에는 별도로 타입핸들러를 만들 필요가 없다.
</br>
3. 데이터베이스에 저장된 자바 코드를 자바의 ENUM으로 변환하거나 암호화/복호화 처리를 하는데 사용하면 유용하다.

</br></br></br>

### 02-02-07. `<objectFactory>`

1. 대부분의 경우 결과셋으로 사용하는 모델을 만들 때 컬럼에 매핑하는 setter 메소드를 호출해서 객체를 만든다. 하지만 setter 메소드가 없으면 자바의 리플렉션을 사용해서 값을 설정한다.
</br>
2. 테이블간의 관계가 복잡하거나 단순히 setter 메소드를 호출하는 것 이상의 과정을 거쳐야 하는 아주 극소수의 경우 objectFactory를 이용할 수 있다.

</br></br></br>

### 02-02-08. `<plugins>`

1. MyBatis가 매핑 구문을 실행하는 과정에서 특정 시점의 처리를 가로채 부가적인 작업을 처리할 수 있다.
</br>
2. 로그를 출력할 수 있고, 파라미터에 대해 공통적으로 타입체크를 하거나, 결과셋에 대한 처리를 추가할 수 있다. (Spring의 AOP나 인터셉터와 유사하다.)

</br></br></br></br>

# 03. MyBatis Mapper by JAVA

## 03-01. Mapper class

### 03-01-01. Mapper의 역할

- sqlSession 객체를 통해 configuration에 등록된 매퍼를 동일 타입으로 반환받아 쿼리를 수행한다.

</br></br>

### 03-01-02. 매퍼 사용 예시

```java
Mapper mapper = sqlSession.getMapper(Mapper.class);
java.util.Date date = mapper.selectSysdate();
```

- 매퍼를 동일한 객체 타입으로 sqlSession 설정에서 반환받아 쿼리를 동작하도록 한다.

</br></br></br>

### 03-01-03. Mapper 인터페이스 어노테이션

- Annotation을 활용하여 문자열로 쿼리를 작성한다.
    - 어노테이션(Annotation)이란
        - 사전적 의미로는 ‘주석’의 뜻을 가지고 있고, 주석처럼 쓰이며 특별한 의미, 기능을 수행하도록 하는 기술이다.
        - 프로그램에 추가 정보를 제공해주는 메타데이터로 볼 수 있다.
- 메소드명은 쿼리를 찾기 위한 key이고, 쿼리 수행 결과를 반환할 자료형을 명시한다.
    
    </br></br>
    
1. @Results
    1. 쿼리 수행 결과를 받아올 ResultMap을 설정한다.
    2. @Result는 각각 DTO객체의 필드명(= property 속성)과 대상 테이블(= column 속성)의 컬럼명을 매핑시킨다.
    3. @Result의 속성 중 id가 true이면 해당 값이 매핑되는 테이블의 PK임을 의미한다.
    4. 사용 예시
    
    ```java
    @Results(id="menuResultMap", value = {
    	@Result(id = true, property = "code", column = "MENU_CODE"),
    	@Result(property = "name", column = "MENU_NAME"),
    	@Result(property = "price", column = "MENU_PRICE"),
    	@Result(property = "categoryCode", column = "CATEGORY_CODE"),
    	@Result(property = "orderableStatus", column = "ORDERABLE_STATUS"),
    })
    ```
    </br></br>
2. @Select
    1. 조회 쿼리를 작성하며, @Results를 바로 위에 작성해 반환 타입을 지정하거나 @ResultMap 어노테이션을 추가해 재사용하도록 지정한다.
    2. 사용 예시
        
        ```java
        @Select("SELECT \n" +
                    "       MENU_CODE\n" +
                    "     , MENU_NAME\n" +
                    "     , MENU_PRICE\n" +
                    "     , CATEGORY_CODE\n" +
                    "     , ORDERABLE_STATUS\n" +
                    "  FROM TBL_MENU\n" +
                    " WHERE ORDERABLE_STATUS = 'Y'\n" +
                    "   AND MENU_CODE = #{ code }")
            @ResultMap("menuResultMap")
            MenuDTO selectMenuByCode(int code);
        ```
    </br></br>    
    
3. @Insert, @Update, @Delete
    1. 각각 삽입, 수정, 삭제 쿼리를 작성하며 반환 타입은 기본적으로 작업이 수행된 로우 갯수를 담은 정수형이다.
    2. @Insert 사용 예시
        
        ```java
        @Insert("INSERT\n" +
                    "  INTO TBL_MENU\n" +
                    "(\n" +
                    "  MENU_NAME\n" +
                    ", MENU_PRICE\n" +
                    ", CATEGORY_CODE\n" +
                    ", ORDERABLE_STATUS\n" +
                    ")\n" +
                    "VALUES\n" +
                    "(\n" +
                    "  #{ name }\n" +
                    ", #{ price }\n" +
                    ", #{ categoryCode }\n" +
                    ", 'Y'\n" +
                    ")")
            int insertMenu(MenuDTO menu);
        ```
        
    3. @Update 사용 예시
        
        ```java
        @Update("UPDATE\n" +
                    "        TBL_MENU\n" +
                    "   SET MENU_NAME = #{ name }\n" +
                    "     , MENU_PRICE = #{ price }\n" +
                    "     , CATEGORY_CODE = #{ categoryCode }\n" +
                    " WHERE MENU_CODE = #{ code }")
            int updateMenu(MenuDTO menu);
        ```
        
    4. @Delete 사용 예시
        
        ```java
        @Delete("DELETE\n" +
                    "  FROM TBL_MENU\n" +
                    " WHERE MENU_CODE = #{ code }")
            int deleteMenu(int code);
        ```
        
</br></br></br></br>

# 04. MyBatis Mapper by XML

## 04-01. MyBatis Mapper XML

### 04-01-01. Mapper.xml 파일의 역할

💡 mapper.xml에는 사용하고자 하는 쿼리나 결과로 받을 객체(= resultMap)를 선언할 수 있다.

</br></br>

### 04-01-02. Mapper XML 작성 시 유의사항

1. Mapper 인터페이스와 동일한 패키지에 위치해야 한다.
    1. 파일 경로는 src > main > resources 하위에 폴더를 생성하여 지정하도록 하고, Mapper 인터페이스 클래스와 동일한 패키지 구조로 컴파일 되도록 경로를 설정해야 한다. 
    2. IntelliJ에서는 resources와 src가 동급으로 처리되므로 하위 폴더 구조를 동일하게 생성해야 이를 맞출 수 있다.
    </br>
2. Mapper 인터페이스의 풀클래스명을 namespace로 지정해야 한다.
    1. namespace 속성은 해당 매퍼를 구분하는 id와 같은 역할이므로 필수로 지정해야 한다.
    </br>
3. Mapper 인터페이스와 매퍼 XML의 파일명이 동일해야 한다.
</br>
4. Mapper 인터페이스에 작성한 메소드의 이름과 id가 일치하고, 반환 타입이 일치하는 쿼리문을 모두 작성해야 한다.

</br></br></br>

### 04-01-03. MyBatis Mapper 파일 작성 방법

1. xml 파일 최상단에 다음과 같이 xml 형식을 지정하여 이하의 설정 내용이 MyBatis Mapper 설정임을 선언한다.
    
    ```xml
    <?xml version="1.0" encoding="UTF-8" ?>
    <!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
    ```
    </br></br>
2. <mapper> 태그를 작성하고, 외부에서 접근할 수 있는 이름인 namespace 속성을 기입한다. 
    
    ```xml
    <?xml version="1.0" encoding="utf-8"?>
    <!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
    <mapper namespace="Member">
    . . .
    </mapper>
    ```
    </br></br>
3. 이후 작성이 필요한 CRUD 및 resultMap 설정 등의 태그를 <mapper> 태그 아래로 작성한다.

</br></br></br></br>


## 04-02. MyBatis Mapper 태그

### 04-02-01. `<resultMap>`

1. DB에서 조회한 결과 데이터를 객체에 원하는 객체의 필드에 담아 반환하는 방법을 정의한다.
    
    </br>
    
2. 해당 태그의 id 속성은 해당 resultMap을 구분하는 명칭이고, type 속성은 대상 객체의 필드를 가진 클래스의 풀클래스명을 작성한다. (단, MyBatis 설정 시 별칭(typeAlias)을 지정했으면 별칭으로 사용 가능하다.)
    
    </br>
    
3. `<resultMap>`태그의 속성은 다음 표와 같다.
    
    
    | 속성명 | 설명 |
    | --- | --- |
    | id | 매핑 구문에서 결과 매핑을 사용할 때 구분하기 위한 ID |
    | type | 결과 매핑을 적용하는 대상 객체 타입(= 매핑 구문의 결과 데이터를 저장할 Java 타입지정) |
    | extends | 기존에 정의된 매핑 결과를 상속받아 추가적인 매핑 정보로 확장할 때 사용 |
    | autoMapping | - 결과 매핑을 자동 매핑을 할 것인지를 결정 (기본값: PARTIAL)
    - NONE, PARTIAL, FULL의 세 가지 옵션 설정 가능
    - auto 매핑 설정은 동일한 컬럼명이 있으면 위험성을 가지므로 사용하지 않는 것이 안전함 |
    
    </br></br>
4. `<resultMap>` 태그의 하위 엘리먼트는는 다음과 같다.
    1. `<id>` : 객체와 매칭되는 테이블의 Primary Key를 의미한다.
    2. `<result>` : 객체와 매칭되는 테이블의 Primary Key 외의 모든 컬럼을 의미한다.
    3. `<constructor>` : 객체화되는 클래스의 생성자에 결과를 삽입하기 위해 사용한다. 
        - `<idArg>`, `<arg>` 하위 엘리먼트가 있다.
        - 생성자는 순서와 타입을 맞춰서 사용해야 한다.
    4. `<association>` : 복잡한 타입의 연관 관계로 1:1 포함 관계인 경우 사용한다.
    5. `<collection>` : 복잡한 타입의 연관 관계로 1:다 포함 관계인 경우 사용한다.
    6. `<discriminator>` : 조건에 따라 다른 resultMap이 매핑되도록 한다.
    
    </br></br>

5. resultMap의 type 속성은 실제로 구현해 놓은 자바 POJO 객체를 사용해야 한다.
    - POJO란 Plain Old Java Project의 약어로, 특정 자바 모델이나 기능, 프레임워크 등을 따르지 않는 자바 오브젝트를 지칭하는 말이다.
    </br></br>
6. 사용 예시
    
    ```xml
    <resultMap id="resultMember" type="Member">
    	<id property="userId" column="USER_ID" />
    	<result property="password" column="PASSWORD" />
    	<result property="userName" column="USER_NAME" />
    	. . .
    </resultMap>
    ```
    
    - 속성 중 property는 객체의 필드명이고, column은 매핑되는 테이블의 컬럼명이다.

    </br></br></br>

### 04-02-02. `<select>`

1. SQL 조회 구문을 작성할 때 쓰인다.
    </br></br>
    
2. 쿼리id와 반환할 타입을 설정하고 태그 내부에 쿼리문을 작성한다. 
    
    ※ 태그 내부에 작성한 쿼리문 끝에는 세미콜론을 작성하지 않는다.
    
    - resultMap 속성 : 매퍼 파일에서 미리 설정한 resultMap을 리턴 타입으로 이용하는 경우에 작성한다.
    - resultType 속성 : 이미 정의되어 있는 객체 타입을 리턴 타입으로 이용하는 경우에 작성한다.
    </br></br>
3. 파라미터는 *#{ field }* 또는 *${ field }* 형태로 기술하며 PreparedStatement의 ?(=placeholder)의 역할을 한다.
    - #{ field } 형태와 ${ field } 형태 모두 작성 가능하나, #{ field } 형태 사용을 권장한다.
        - **#{ *field* }** : 쿼리 생성 시 넘겨준 필드 값에 자동으로 싱글 쿼테이션 붙여준다.
        - **${ *field*** **}** : 사용자가 넘긴 값 그대로 필터 없이 현출되므로, 문자이면 보낼 때 쿼테이션 붙여서 보내야 한다.
    - parameterType이 객체인 경우, getter 메소드를 호출하므로 해당 객체에 반드시 getter 메소드가 작성되어야 한다.
    - 파라미터가 한 개인 경우 바인딩 되는 이름을 무엇으로 작성하든 무관하고, 파라미터 타입을 지정하지 않아도 된다.
    </br></br>
4. 사용 예시
    
    ```xml
    <select id="memberInfo" parameterType="string" resultMap="resultMember">
    	SELECT * FROM MEMBER WHERE ID = #{ userid }
    </select>
    ```
    </br></br>
5. `<select>` 태그의 주요 속성
    
    
    | **속성명** | **내용** |
    | --- | --- |
    | id | 구문을 찾기 위해 사용될 수 있는 namespace 내 유일한 구분자 |
    | parameterType | 구문에 전달될 파라미터의 클래스명(패키지 경로 포함)이나 별칭 |
    | resultType | - return 되는 타입의 패키지 경로를 포함한 전체 클래스명이나 별칭 - collection인 경우 list, arraylist로 설정 가능 |
    | resultMap | 사용할 resultMap의 id |
    | flushCache | - true 설정하면 구문 호출 시마다 로컬, 2nd 레벨 cache가 지워짐(flush) - 기본값 = false |
    | useCache | - true 설정하면 구문의 결과를 2nd 레벨 cache에 저장 - 기본값 = true |
    | timeout | - 예외 발생 전에 데이터베이스의 요청 결과를 기다리는 최대 시간 설정 - 드라이버에 따라 지원하지 않을 수 있음 |
    | statementType | - MyBatis에게 사용하게 할 Statement 선택 가능 (STATEMENT, PREPARED, CALLABLE 중 하나) (Statement, PreparedStatement, CallableStatement 사용하게 하는 것) - 기본값 = PreparedStatement |
    | fetchSize | 지정된 수 만큼의 결과를 반환하게 하는 드라이버 힌트 형태의 값 (디폴트: 설정안함) |
    | resultSetType | - ResultSet의 커서 이동 방향을 지정 (기본값: FORWARD_ONLY) - FORWARD_ONLY, SCROLL_SENSITIVE, SCROLL_INSENCITIVE 중 하나로 설정 (1) FORWARD_ONLY : 커서가 앞으로만 이동 (2) SCROLL_SENSITIVE : 커서가 앞뒤로 이동 및 ResultSet 객체 생성 후 추가 및 삭제된 데이터도 볼 수 있음 (3) SCROLL_INSENSITIVE : 커서가 앞뒤로 이동할 수 있지만 ResultSet 객체 생성 후 추가 및 삭제된 데이터는 볼 수 없음 |
    | databaseId | - 설정된 databaseIdProvider가 있으면 databaseId 속성이 없는 모든 구문을 로드하거나 일치하는 databaseId와 함께 로드함 - 같은 구문에서 databaseId가 있거나 없는 경우가 모두 있다면 뒤에 나온 것 무시 |

    </br>

    - (참고) FlushCache와 useCache
        - 일반적으로 쿼리를 수행할 때, 쿼리의 결과나 호출되는 내용이 변동이 없는 정적 쿼리나 결과라면 수행 시마다 굳이 새로운 쿼리로 생성하여 호출하거나 새로운 결과를 받아 올 필요가 없다.
        - 이런 상황에 대해 Mybatis에서는 Cache라는 저장소를 내장한다. 반복되는 정적 쿼리의 호출이나 결과에 대한 내용을 한 번 이상 실행하면 Cache에 미리 저장해둠으로써 재호출에 소요되는 시간을 절약할 수 있도록 한다.

</br></br></br>

### 04-02-03. `<insert>`, `<update>`, `<delete>`

1. 데이터 삽입, 수정, 삭제 작업을 수행할 INSERT, UPDATE, DELETE 쿼리문을 작성하는 태그로, 태그의 설정이 동일하다.
    </br>
    
2. 파라미터로 객체 타입을 받는 경우, 해당 객체의 필드명으로 바인딩하여 사용한다.
    - `<select>`태그와 마찬가지로 파라미터의 getter 메소드를 호출하므로 해당 객체에 반드시 getter 메소드가 작성되어야 한다.
    - 파라미터 타입이 객체인 경우 fullClass명으로 작성하거나 미리 등록한 별칭을 이용한다.
    </br>
3. 세 개의 태그 모두 resultType이 _int로 기본 설정되어 있어, 수행 결과를 정수형으로 반환하므로 작성하지 않아도 무방하다.
    </br>
    
4. `<insert>` 사용 예시
    
    ```xml
    <insert id="insertMember" parameterType="Member" flushCache="true" statementType="PREPARED" keyProperty="" keyColumn="" useGeneratedKeys="true" timeout="20">
    	INSERT INTO MEMBER 
    	VALUES(#{id}, #{passwd}, #{name},	#{email}, #{gender}, #{age}, #{phone}, #{address}, DEFAULT)
    </insert>
    ```
    </br>
5. `<update>` 사용 예시
    
    ```xml
    <update id="updateMember" parameterType="Member" flushCache="true" statementType="PREPARED" timeout="20">
    	UPDATE MEMBER
    		 SET PASSWD = #{passwd}, 
    					EMAIL = #{email}, 
    					AGE = #{age},
    					PHONE = #{phone},
    					ADDRESS = #{address}
    		WHERE ID = #{id}
    </update>
    ```
    </br>
6. `<delete>` 사용 예시
    
    ```xml
    <delete id="deleteMember" parameterType="string" flushCache="true" statementType="PREPARED" timeout="20">
    	DELETE FROM MEMBER WHERE ID = #{userid}
    </delete>
    ```
    </br>
7. `<insert>`, `<update>`, `<delete>` 태그의 주요 속성
    
    
    | **속성명** | **내용** |
    | --- | --- |
    | id | 구문을 찾기 위해 사용될 수 있는 namespace 내 유일한 구분자 |
    | parameterType | 구문에 전달될 파라미터의 클래스명(패키지 경로 포함)이나 별칭 |
    | flushCache | - true로 설정하면 구문 호출 시마다 캐시 삭제(flush) - 기본값 = false |
    | timeout  | - 예외 발생 전 데이터베이스의 요청 결과를 기다리는 최대 시간 설정 - 드라이버에 따라 지원하지 않을 수 있음 |
    | statementType | - JDBC 구문 타입을 지정 (기본값: PREPARED) - STATEMENT, PREPARED, CALLABLE 중 하나 사용 가능 |
    | useGeneratedKeys | - insert, update 에만 적용 - 데이터베이스에서 내부적으로 생성한 키(예: MySQL또는 SQL Server의 자동 증가 필드)를 받는 JDBC getGeneratedKeys method를 사용하도록 설정 - 기본값 = false |
    | keyProperty | - insert, update 에만 적용 - getGeneratedKeys method나 insert 구문의 selectKey태그의 설정 - select문의 결과를 저장할 property 지정 - 설정하지 않는 것이 default - 여러 컬럼을 사용한다면 property명에 콤마를 구분자로 나열 가능 |
    | keyColumn | - insert 에만 적용 - 생성 키를 가진 테이블의 컬럼명 설정 (키 컬럼이 테이블의 첫 번째 행이 아닌 데이터베이스에서만 필요) |


    </br></br></br>

### 04-02-04. `<cache>`와 `<cache-ref>`

1. 두 태그 모두 캐시를 설정하는 역할을 한다.
    - `<cache>`태그는 는 현재 네임스페이스에 대한 캐시를 설정하고, `<cache-ref>`태그는 다른 네임스페이스에 대한 캐시 설정을 참조할 때 사용한다.
    </br>

    ❓ **Cache란**
    
    - 데이터나 값을 미리 복사해 놓은 임시 장소이다.
    - 캐시에 데이터를 미리 복사해 놓으면 계산이나 접근 시간 없이 더 빠른 속도로 데이터에 접근할 수 있다.

</br>
    
2. 캐시의 기본(default) 설정은 다음과 같다.
    1. 매퍼 XML의 모든 select 구문의 결과를 캐시에 저장한다.
    2. 매퍼 XML의 insert, update, delete는 모두 캐시를 지운다.
    3. 가장 오래 사용하지 않은 캐시를 지우는 알고리즘(LRU-Least Recently Used)을 사용한다.
    4. 애플리케이션이 실행되는 동안 캐시를 유지한다. 특정 시점에 사라지거나 하지 않는다.
    5. 캐시는 최대 1024개까지 저장한다.
    6. 캐시는 읽기/쓰기가 모두 가능하다.
    </br>
3. 캐시 사용 예시
    
    ```xml
    <cache eviction="LRU" flushInterval="1000" size="512" readOnly="true"/>
    ```
    </br>
4. `<cache>`태그의 속성
    
    
    | 속성명 | 설명 |
    | --- | --- |
    | eviction | - 캐시 알고리즘의 종류 (기본값: LRU) - FIFO, SOFT, WEAK로 설정 가능 |
    | flushInterval | - 설정된 캐시의 유지 시간을 양수의 밀리초 단위로 설정 |
    | size | - 캐시에 저장할 객체의 수를 지정 (기본값: 1024) |
    | readonly | 읽기전용 설정으로 캐시 데이터 변경 불가하게 함 |
    
    </br>
5. 캐시의 제약 사항
    1. 기본적으로 로컬 영역이므로 서버를 여러 대 두는 경우 캐시 내용이 서로 다를 수 있다.
        
        → 서버마다 캐시 내용을 동일하게 맞추기 위해서는 분산캐시를 사용해야 한다.
        
    2. 캐시의 타이머 설정은 가능한 반면 스케쥴링은 불가능하다.
    
    ⇒ 이러한 제약사항을 해결하기 위해 Cachenix, Ehcache, Hazelcast, OsCache 등을 사용한다.

    </br></br></br>

### 04-02-05. `<sql>`

1. 매핑 구문에서 공통으로 사용할 수 있는 SQL 문자열의 일부를 정의하고 재사용하기 위해 사용한다.
    
    </br>
2. 사용 예시
    1. `<sql>` 작성
        
        ```xml
        <sql id="columns">
            MENU_CODE
          , MENU_NAME
          , MENU_PRICE
          , CATEGORY_CODE
          , ORDERABLE_STATUS
        </sql>
        ```
        
    2. `<sql>` 활용
        
        ```xml
        <select id="selectSqlTest" resultMap="menuResultMap2">
            SELECT
            <include refid="columns"/>
              FROM TBL_MENU A
             WHERE A.ORDERABLE_STATUS = 'Y'
        </select>
        ```

</br></br></br>
