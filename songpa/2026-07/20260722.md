#### [학습 내용]

* **LLM Memory의 개념과 역할**

  * Memory는 이전 대화와 사용자 정보를 저장하여 이후 답변에 반영하는 기능임을 이해했다.
  * 단순히 대화 내용을 모두 저장하는 것이 아니라 Profile Memory, Conversation Memory, Summary Memory를 함께 관리하는 구조를 구현했다.

</br></br>

* **Profile Memory 구현 방법**

  * 사용자의 이름, 관심사, 목표, 학습 수준, 선호하는 설명 방식 등을 추출하여 Profile에 저장하는 기능을 구현했다.
  * 이후 사용자가 자신의 정보를 다시 질문하면 저장된 Profile을 활용하여 답변하도록 구현했다.
  * 새로운 정보를 입력하면 기존 정보를 업데이트하는 방식도 함께 실습했다.

</br></br>

* **Conversation Memory와 Memory Window**

  * 모든 대화를 프롬프트에 전달하는 대신 최근 N개의 대화만 사용하는 Memory Window를 구현했다.
  * Window 크기를 변경하면서 최근 대화만 사용하는 경우와 전체 대화를 사용하는 경우를 비교했고, Context 길이를 효율적으로 관리하는 방법을 이해했다.

</br></br>

* **Summary Memory의 필요성과 구현 방법**

  * 누적된 대화를 요약하여 짧은 Summary로 관리하는 방식을 구현했다.
  * 전체 대화, 최근 대화, Summary의 길이를 비교하며 Summary Memory가 토큰 사용량을 줄이는 데 효과적이라는 점을 확인했다.

</br></br>

* **Memory 관리 기능**

  * 특정 Profile 정보나 전체 Profile을 삭제하는 기능을 구현했다.
  * 여러 사용자를 Session 단위로 분리하여 각각의 Memory를 관리하는 구조를 구현했다.
  * Memory를 JSON 파일로 저장하고 프로그램 재실행 후 다시 불러와 이전 상태를 복원하는 기능을 실습했다.

</br></br>

* **LLM과 Memory를 결합하는 방법**

  * Profile, Summary, 최근 대화를 하나의 프롬프트로 구성하여 LLM에게 전달하는 구조를 구현했다.
  * 사용자의 학습 수준이나 선호하는 설명 방식을 반영하는 개인화된 답변을 생성하는 방법을 이해했다.

</br></br>

* **Memory에서의 개인정보 관리**

  * 비밀번호, API Key, 주민등록번호 등 민감정보를 탐지하여 저장하지 않는 기능을 구현했다.
  * 허용된 사용자 정보만 Profile에 저장하고, 민감정보는 대화 기록에서도 제거하도록 설계했다.
  * Memory 시스템에서도 개인정보 보호가 중요한 요소임을 이해했다.

</br></br></br>

#### [느낀 내용]

* LLM의 Memory는 단순히 이전 대화를 저장하는 기능이 아니라 사용자 정보를 구조화하여 관리하고, 필요한 정보만 효율적으로 활용하는 시스템이라는 점이 인상적이었다.
* Conversation Memory, Summary Memory, Profile Memory를 적절히 조합하면 긴 대화에서도 토큰을 절약하면서 사용자 맞춤형 답변을 제공할 수 있다는 점을 이해할 수 있었다.
* 여러 사용자의 Session을 분리하고 민감정보를 저장하지 않는 기능을 구현하면서 실제 AI 서비스를 개발할 때 Memory 관리와 개인정보 보호가 매우 중요하다는 것을 느꼈다.

</br>

#### [활용 방안]

* AI 챗봇 개발 시 Profile Memory와 Conversation Memory를 함께 활용하기
* 긴 대화에서는 Summary Memory와 Memory Window를 적용하여 토큰 사용량을 줄이면서도 중요한 문맥을 유지하도록 설계하기
* 여러 사용자가 동시에 사용하는 서비스에서는 Session별 Memory를 분리하고 JSON 또는 DB를 이용해 Memory를 영속적으로 저장하기
* 개인정보 보호를 위해 민감정보 탐지 및 저장 제한 기능추가하기
