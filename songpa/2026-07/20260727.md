* 단원명 : LLM
* 학습 주제 : Fast API

---


#### [학습 내용]

* **REST API CRUD 설계**

  * FastAPI를 이용해 조회(GET), 전체 수정(PUT), 부분 수정(PATCH) API를 구현했다.
  * PUT은 자원을 전체 교체하고, PATCH는 `exclude_unset=True`를 이용해 전달된 필드만 수정하는 차이를 이해했다.
  * Query Parameter를 활용하여 완료 여부, 우선순위, 키워드 등 다양한 조회 조건을 적용하는 방법을 실습했다.

  </br></br>

* **APIRouter를 이용한 프로젝트 구조화**

  * `students`, `courses`와 같이 자원별 Router를 분리하고 `include_router()`를 통해 하나의 FastAPI 애플리케이션으로 구성하는 방법을 익혔다.
  * 공통 Schema를 별도 파일에서 관리하여 여러 Router에서 재사용하는 구조를 이해했다.
  * Swagger(OpenAPI)에서 Router별 Tag를 이용해 API가 자동으로 그룹화되는 것도 확인했다.

  </br></br>

* **Form 데이터와 파일 업로드 처리**

  * `Form`, `UploadFile`을 이용해 multipart/form-data 요청을 처리하는 방법을 실습했다.
  * 업로드 파일의 MIME Type과 확장자를 검증하고, 파일 크기를 제한하여 안전하게 업로드하는 기능을 구현했다.
  * UUID를 이용해 저장 파일명을 생성하고, 메타데이터를 JSON 파일로 함께 저장하는 방식을 학습했다.

  </br></br>

* **파일 입출력(File I/O)**

  * `pathlib.Path`를 이용하여 파일 읽기, 쓰기, 복사를 구현했다.
  * `resolve()`를 활용하여 지정한 디렉터리 밖으로 접근하는 경로(Path Traversal)를 방지하는 방법을 익혔다.
  * API와 별개로 파일을 영속적으로 저장하고 관리하는 구조를 이해했다.

  </br></br>

* **Spring Boot와 FastAPI 연동**

  * Spring Boot의 `RestClient`를 이용하여 FastAPI 서버의 API를 HTTP로 호출하는 구조를 구현했다.
  * FastAPI 서버의 Health Check를 호출하고, 서버 연결 실패 시 적절한 예외 처리를 수행하는 방법을 실습했다.
  * FastAPI를 AI 서비스나 파일 서비스로 두고, Spring Boot가 이를 호출하는 마이크로서비스 형태의 구조를 이해했다.

</br></br></br>

#### [느낀 내용]

* Router를 이용한 프로젝트 구조화와 파일 업로드 기능은 실무에서도 자주 사용될 것이라는 생각이 들었다.

* Spring Boot에서 HTTP API를 통해 FastAPI와 통신하는 구조를 구현하면서, 서로 다른 언어와 프레임워크도 API를 통해 자연스럽게 협력할 수 있다는 점이 인상적이었다.

* 앞으로 AI 기능도 FastAPI에서 제공하고 Spring Boot에서 호출하는 구조를 적용하면 확장성과 유지보수 측면에서 유리할 것이라는 점을 이해하게 되었다.

</br>

#### [활용 방안]

* FastAPI 프로젝트를 개발할 때 APIRouter와 Schema를 분리하여 기능별로 구조화하기

* REST API를 설계할 때 PUT과 PATCH의 역할을 구분하고, 상황에 맞는 HTTP Method를 사용하기
