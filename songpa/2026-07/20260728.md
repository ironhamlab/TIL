* 단원명 : LLM
* 학습 주제 : Fast API, LangGraph

#### [학습 내용]

* **FastAPI와 Spring Boot 파일 업로드 연동**

  * FastAPI에서 `UploadFile`, `File`, `Form`을 이용하여 `multipart/form-data` 요청을 처리하는 방법을 실습했다.
  * 업로드 파일의 MIME Type과 확장자를 함께 검증하고, 파일 크기를 제한하여 안전하게 파일을 저장하는 기능을 구현했다.
  * UUID를 이용해 저장 파일명을 생성하고, 파일 정보는 JSON 형태의 메타데이터로 함께 저장하는 방식을 학습했다.
  * Spring Boot의 `RestClient`를 이용하여 `MultipartFile`을 FastAPI로 전달하고, HTTP API를 통해 파일 업로드를 수행하는 구조를 구현했다.
  * FastAPI가 반환한 상태 코드를 Spring Boot에서도 적절하게 처리하여 서비스 간 예외를 전달하는 방법을 익혔다.

  </br></br>

* **LangChain과 LangGraph의 차이**

  * LangChain은 실행 순서가 고정된 작업을 연결하는 데 적합하고, LangGraph는 분기와 반복, 상태 공유가 필요한 작업을 구성하는 데 적합하다는 점을 학습했다.
  * 같은 검색 및 답변 생성 작업을 LangChain과 LangGraph로 각각 구현하여 두 방식의 구조와 실행 흐름을 비교했다.
  * 단순한 파이프라인은 LangChain으로 충분하지만, 복잡한 AI Agent는 LangGraph가 적합하다는 점을 이해했다.

  </br></br>

* **LangGraph의 State, Node, Edge 구조**

  * `TypedDict`를 이용하여 여러 Node가 공유하는 State를 정의하는 방법을 학습했다.
  * Node는 State를 읽어 필요한 작업만 수행하고 변경된 값만 반환해도 LangGraph가 자동으로 State를 병합한다는 점을 이해했다.
  * Edge를 이용하여 Node의 실행 순서를 정의하고 `START`, `END`를 통해 Graph의 시작과 종료를 구성하는 방법을 실습했다.
  * 실행 경로를 State에 저장하여 Graph가 어떤 순서로 동작했는지 추적하는 방법을 익혔다.

  </br></br>

* **Reducer를 이용한 State 병합**

  * 여러 Node가 같은 State를 수정할 경우 기본적으로 값이 덮어써질 수 있다는 점을 확인했다.
  * `Annotated[list[str], operator.add]`를 이용하여 여러 Node의 결과를 하나의 리스트에 누적하는 Reducer를 구현했다.
  * 장소, 예산, 식사, 교통 등 여러 조사 결과를 하나의 State에 순차적으로 저장하는 구조를 학습했다.

  </br></br>

* **Conditional Edge와 Query Routing**

  * 질문의 의도를 먼저 분류한 뒤 필요한 Node만 실행하는 Query Routing 구조를 구현했다.
  * `classify` Node에서 질문을 분석하고 `add_conditional_edges()`를 이용해 분기하는 방법을 실습했다.
  * 모든 질문에 동일한 작업을 수행하는 것이 아니라 질문의 종류에 따라 다른 실행 경로를 선택하는 구조를 이해했다.

  </br></br>

* **LangGraph 기반 RAG 구성**

  * OpenAI Embedding과 `InMemoryVectorStore`를 이용하여 문서를 Embedding하고 검색하는 구조를 구현했다.
  * `retrieve` Node에서 관련 문서를 검색하여 Context를 생성하고, `generate` Node에서 검색된 Context만 근거로 LLM이 답변하도록 구성했다.
  * Retrieval 단계와 Generation 단계를 분리하여 RAG의 오류 원인을 각각 확인하는 방법을 학습했다.
  * Query Router를 이용하여 RAG가 필요한 질문만 VectorStore를 검색하고, 일반 질문은 LLM이 바로 처리하는 구조를 이해했다.

</br></br></br>

#### [느낀 내용]

* FastAPI와 Spring Boot를 HTTP API로 연동하면서 서로 다른 언어와 프레임워크도 공통된 API 규칙만 있으면 독립적으로 협력할 수 있다는 점이 인상적이었다.

* LangGraph는 단순히 LangChain의 확장판이 아니라 AI 작업을 State와 Node 단위로 나누어 실행 흐름을 관리하는 프레임워크라는 점을 이해할 수 있었다.

* 특히 RAG를 Retrieval과 Generation 단계로 분리하면 답변이 잘못되었을 때 검색 문제인지, LLM 생성 문제인지 쉽게 분석할 수 있다는 점이 가장 유용하게 느껴졌다.

* 모든 질문에 RAG를 수행하는 것이 아니라 Query Router를 이용해 필요한 질문만 검색하는 구조가 실제 서비스의 성능과 비용을 고려한 설계라는 점도 인상적이었다.

</br>

#### [활용 방안]

* FastAPI를 AI 및 파일 처리 전용 서비스로 분리하고, Spring Boot에서는 HTTP API를 통해 호출하는 구조를 프로젝트에 적용하기

* LangGraph를 사용할 때는 State, Node, Edge를 명확하게 분리하여 AI 작업 흐름을 설계하기

* 여러 Node의 결과를 함께 사용해야 하는 경우 Reducer를 적용하여 State를 안전하게 병합하기

* RAG를 구현할 때 Retrieval과 Generation 단계를 분리하여 검색 결과와 답변을 각각 검증할 수 있는 구조로 개발하기

* Query Router를 이용하여 질문 유형에 따라 RAG, 일반 LLM, 계산 등 필요한 처리 방식만 수행하도록 설계하기
