#### [학습 내용]

* **리눅스의 기본 구조와 명령어 사용**

  * 리눅스 환경에서 현재 작업 중인 디렉터리를 확인하고 파일과 디렉터리를 이동하는 기본 명령어를 학습했다.
  * `pwd`를 이용해 현재 경로를 확인하고, `ls`를 이용해 현재 디렉터리의 파일과 디렉터리 목록을 조회하는 방법을 익혔다.
  * `cd`를 이용해 원하는 디렉터리로 이동하고, 절대 경로와 상대 경로의 차이를 이해했다.
  * `.`은 현재 디렉터리, `..`은 상위 디렉터리, `~`는 현재 사용자의 홈 디렉터리를 의미한다는 점을 학습했다.

  </br></br>

* **파일과 디렉터리 관리**

  * `mkdir`를 이용해 새로운 디렉터리를 생성하고, `touch`를 이용해 빈 파일을 생성하는 방법을 실습했다.
  * `cp`를 이용해 파일이나 디렉터리를 복사하고, `mv`를 이용해 파일을 이동하거나 이름을 변경하는 방법을 익혔다.
  * `rm`을 이용해 파일을 삭제하고, `rm -r`을 이용해 디렉터리 내부의 파일까지 함께 삭제하는 방법을 학습했다.
  * 리눅스에서는 삭제한 파일을 복구하기 어려울 수 있으므로 `rm` 명령어를 사용할 때 경로를 반드시 확인해야 한다는 점을 이해했다.

  </br></br>

* **파일 내용 확인과 검색**

  * `cat`을 이용해 텍스트 파일의 전체 내용을 출력하는 방법을 학습했다.
  * `head`와 `tail`을 이용해 파일의 앞부분과 뒷부분만 확인하는 방법을 익혔다.
  * `tail -f`를 사용하면 로그 파일에 새롭게 추가되는 내용을 실시간으로 확인할 수 있다는 점을 이해했다.
  * `grep`을 이용해 파일이나 명령어 출력 결과에서 특정 문자열을 검색하는 방법을 실습했다.
  * 파이프(`|`)를 이용해 앞 명령어의 실행 결과를 다음 명령어의 입력으로 전달하는 방법을 학습했다.

  </br></br>

* **프로세스와 시스템 상태 확인**

  * `ps`를 이용해 현재 실행 중인 프로세스를 확인하는 방법을 학습했다.
  * 프로세스 ID인 PID를 이용해 특정 프로세스를 식별하고, 필요한 경우 `kill` 명령어로 종료할 수 있다는 점을 이해했다.
  * `top`을 통해 CPU와 메모리 사용량, 실행 중인 프로세스 등 시스템 상태를 확인하는 방법을 익혔다.
  * `df`를 이용해 디스크 전체 사용량을 확인하고, `du`를 이용해 특정 파일이나 디렉터리의 용량을 확인하는 방법을 학습했다.

  </br></br>

* **권한과 관리자 명령어**

  * 리눅스의 파일과 디렉터리에는 읽기, 쓰기, 실행 권한이 설정된다는 점을 학습했다.
  * `ls -l`을 이용해 파일의 권한, 소유자, 그룹 등의 상세 정보를 확인하는 방법을 익혔다.
  * `chmod`를 이용해 파일의 권한을 변경하고, 실행 파일에 실행 권한을 부여하는 방법을 학습했다.
  * 일반 사용자에게 권한이 없는 명령어는 `sudo`를 이용해 관리자 권한으로 실행할 수 있다는 점을 이해했다.
  * 모든 명령어에 습관적으로 `sudo`를 사용하는 것이 아니라 필요한 경우에만 사용해야 한다는 점을 학습했다.

  </br></br>

* **Docker의 개념과 필요성**

  * Docker는 애플리케이션과 실행에 필요한 라이브러리, 설정을 하나의 Container로 묶어 동일한 환경에서 실행할 수 있게 해주는 도구라는 점을 학습했다.
  * 개발자의 로컬 환경과 서버 환경의 차이로 발생하는 문제를 줄이고, 애플리케이션을 빠르게 배포할 수 있다는 장점을 이해했다.
  * 가상 머신은 운영체제 전체를 포함하지만, Docker Container는 호스트 운영체제의 Kernel을 공유하기 때문에 상대적으로 가볍고 실행 속도가 빠르다는 차이를 학습했다.
  * Image는 Container를 생성하기 위한 실행 환경의 원본이고, Container는 Image를 바탕으로 실제 실행된 인스턴스라는 점을 구분했다.

  </br></br>

* **Docker Image와 Container 기본 명령어**

  * `docker pull`을 이용해 Docker Hub 등의 Registry에서 Image를 내려받는 방법을 학습했다.
  * `docker images`를 이용해 로컬에 저장된 Image 목록을 확인하는 방법을 익혔다.
  * `docker run`을 이용해 Image로부터 새로운 Container를 생성하고 실행하는 방법을 실습했다.
  * `docker ps`로 실행 중인 Container를 확인하고, `docker ps -a`로 종료된 Container까지 확인하는 방법을 학습했다.
  * `docker stop`, `docker start`, `docker restart`를 이용해 Container의 실행 상태를 관리하는 방법을 익혔다.
  * `docker rm`을 이용해 Container를 삭제하고, `docker rmi`를 이용해 Image를 삭제하는 방법을 학습했다.

  </br></br>

* **Docker Port와 Volume**

  * Container 내부의 서비스에 외부에서 접근하려면 호스트와 Container의 Port를 연결해야 한다는 점을 학습했다.
  * `-p 호스트포트:컨테이너포트` 형식으로 Port Mapping을 설정하는 방법을 익혔다.
  * Container는 삭제될 수 있는 임시 실행 환경이므로 내부에 저장된 데이터도 함께 사라질 수 있다는 점을 이해했다.
  * Volume을 이용하면 Container와 독립적으로 데이터를 보관할 수 있고, Container를 다시 생성해도 기존 데이터를 사용할 수 있다는 점을 학습했다.
  * 데이터베이스처럼 데이터 보존이 중요한 서비스에서는 Volume 설정이 필요하다는 점을 이해했다.

  </br></br>

* **Docker 로그와 Container 내부 확인**

  * `docker logs`를 이용해 Container에서 출력된 로그를 확인하는 방법을 학습했다.
  * `docker logs -f`를 이용하면 실행 중인 서비스의 로그를 실시간으로 확인할 수 있다는 점을 익혔다.
  * `docker exec`를 이용해 실행 중인 Container 내부에서 명령어를 실행하는 방법을 학습했다.
  * Container가 정상적으로 실행되지 않을 때는 상태만 확인하는 것이 아니라 로그를 먼저 읽어 오류 원인을 파악해야 한다는 점을 이해했다.

  </br></br>

* **Dockerfile을 이용한 Image 생성**

  * Dockerfile은 애플리케이션 Image를 만들기 위한 실행 절차를 정의한 파일이라는 점을 학습했다.
  * `FROM`으로 기반 Image를 선택하고, `WORKDIR`로 Container 내부 작업 디렉터리를 지정하는 방법을 이해했다.
  * `COPY`를 이용해 애플리케이션 파일을 Image 내부로 복사하고, `RUN`을 이용해 의존성을 설치하는 방법을 학습했다.
  * `CMD` 또는 `ENTRYPOINT`를 통해 Container가 시작될 때 실행할 명령어를 정의할 수 있다는 점을 익혔다.
  * `docker build`를 이용해 Dockerfile로 Image를 생성하고, 생성한 Image를 `docker run`으로 실행하는 전체 흐름을 이해했다.

</br></br></br>

#### [느낀 내용]

* 리눅스 명령어는 서버 환경을 다루기 위한 기본 도구이므로 명령어 자체를 외우는 것보다 현재 위치와 명령어의 실행 대상을 확인하는 습관이 중요하다고 느꼈다.

* GUI 없이 명령어만으로 파일, 프로세스, 로그, 시스템 자원을 관리할 수 있다는 점이 처음에는 낯설었지만 서버 문제를 빠르게 확인하는 데 더 효율적일 수 있다는 생각이 들었다.

* Docker는 단순히 프로그램을 실행하는 도구가 아니라 애플리케이션의 실행 환경을 하나의 단위로 관리하는 기술이라는 점을 이해했다.

* Image와 Container, Port와 Volume의 역할을 구분하면서 Docker가 개발 환경 통일과 배포 자동화에 자주 사용되는 이유를 알게 되었다.

* Container 실행에 문제가 있을 때 무조건 다시 실행하는 것이 아니라 `docker ps`로 상태를 확인하고 `docker logs`로 원인을 찾는 과정이 중요하다고 느꼈다.

#### [활용 방안]

* 서버에 접속했을 때 `pwd`, `ls`, `cd`를 이용해 현재 위치와 파일 구조를 먼저 확인하기

* 애플리케이션 장애를 확인할 때 프로세스, 포트, 로그, 디스크와 메모리 사용량을 순서대로 점검하기

* 파일 삭제나 권한 변경처럼 시스템에 영향을 주는 명령어는 실행 전에 대상 경로와 옵션을 다시 확인하기

* 프로젝트 실행 환경을 Docker Image로 구성하여 개발자별 환경 차이로 발생하는 문제 줄이기

* 웹 서버나 데이터베이스 Container를 실행할 때 Port Mapping과 Volume 설정을 명확하게 적용하기

* Container 장애가 발생하면 `docker ps`, `docker logs`, `docker exec`를 이용해 상태와 내부 환경을 단계적으로 확인하기

* 향후 프로젝트에서는 Dockerfile과 Docker Compose를 이용해 애플리케이션과 데이터베이스를 한 번에 실행할 수 있는 개발 환경 구성하기
