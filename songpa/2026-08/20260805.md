#### [학습 내용]

* **VPC(Virtual Private Cloud)**

  * VPC는 AWS에서 독립된 가상 네트워크를 구성하는 서비스라는 점을 학습했다.
  * 하나의 AWS 계정 안에서도 여러 개의 VPC를 생성하여 서로 분리된 네트워크 환경을 구성할 수 있다는 점을 이해했다.
  * VPC 내부에서 Subnet, Route Table, Internet Gateway 등을 이용하여 네트워크를 설계하는 구조를 학습했다.

  </br></br>

* **Subnet 구성**

  * VPC 내부를 여러 개의 Subnet으로 나누어 네트워크를 분리하는 방법을 학습했다.
  * 인터넷과 직접 통신하는 Public Subnet과 외부에서 직접 접근할 수 없는 Private Subnet의 역할을 이해했다.
  * React, ALB와 같은 외부 접근이 필요한 리소스는 Public Subnet에, Spring Boot와 Database는 Private Subnet에 배치하는 구조를 학습했다.

  </br></br>

* **Route Table과 NAT Gateway**

  * Route Table은 Subnet에서 목적지별 네트워크 경로를 정의하는 구성 요소라는 점을 학습했다.
  * Public Subnet은 Internet Gateway를 통해 외부 인터넷과 통신하도록 설정하는 방법을 이해했다.
  * Private Subnet은 NAT Gateway를 이용하여 외부 인터넷으로만 접근하고, 외부에서는 직접 접근할 수 없도록 구성하는 방식을 학습했다.
  * NAT Gateway를 이용하면 Private 서버에서도 패키지 설치나 업데이트와 같은 Outbound 통신이 가능하다는 점을 이해했다.

  </br></br>

* **Bastion Server**

  * Bastion Server는 Private Subnet의 서버에 안전하게 접근하기 위한 중간 접속 서버라는 점을 학습했다.
  * SSH를 외부에 직접 개방하지 않고 Bastion Server를 통해 Private 서버에 접속하는 구조를 이해했다.
  * 운영 서버를 인터넷에 직접 노출하지 않아 보안을 강화할 수 있다는 점을 학습했다.

  </br></br>

* **Application Load Balancer(ALB)**

  * ALB는 클라이언트의 요청을 여러 애플리케이션 서버에 분산하는 Load Balancer라는 점을 학습했다.
  * HTTP 요청의 Host, Path 등의 정보를 기준으로 원하는 Target Group으로 라우팅할 수 있다는 점을 이해했다.
  * 하나의 ALB를 이용하여 여러 서비스로 요청을 분배하는 구조를 학습했다.
  * 서버 장애가 발생한 경우 정상 서버로 요청을 전달하여 서비스 가용성을 높일 수 있다는 점을 이해했다.

  </br></br>

* **HTTP 통신 설정**

  * HTTP 요청이 Client → ALB → Spring Boot 서버 순서로 전달되는 흐름을 학습했다.
  * Security Group과 Port 설정을 통해 필요한 서비스만 통신하도록 구성하는 방법을 익혔다.
  * Frontend와 Backend가 서로 다른 서버에서 동작할 경우 API 주소와 CORS 설정이 필요하다는 점을 이해했다.

  </br></br>

* **React 애플리케이션 배포**

  * React 프로젝트를 Build하여 정적 파일을 생성한 후 웹 서버를 통해 배포하는 과정을 학습했다.
  * React는 Browser에서 실행되는 Frontend이므로 API 요청 주소를 Backend 환경에 맞게 설정해야 한다는 점을 이해했다.
  * Build된 React 애플리케이션을 Public 환경에서 서비스하는 구조를 학습했다.

  </br></br>

* **Spring Boot 애플리케이션 배포**

  * Spring Boot 애플리케이션을 서버에서 실행하고 외부 요청을 처리하는 과정을 학습했다.
  * Spring Boot 서버는 직접 외부에 노출하지 않고 ALB를 통해 요청을 전달받는 구조를 이해했다.
  * Application 실행과 Port 설정, 환경 변수 등을 서버 환경에 맞게 구성하는 방법을 학습했다.

  </br></br>

* **React와 Spring Boot 통합 배포 구조**

  * React Frontend와 Spring Boot Backend를 분리하여 배포하는 구조를 학습했다.
  * 사용자의 요청은 React 화면에서 시작되고, 필요한 데이터는 HTTP API를 통해 Spring Boot에서 처리하는 구조를 이해했다.
  * AWS에서는 ALB, VPC, Subnet 등을 활용하여 Frontend와 Backend를 안전하게 연결하는 전체 아키텍처를 학습했다.

</br></br></br>

#### [느낀 내용]

* 지금까지는 애플리케이션 개발에 집중했다면, 이번에는 네트워크와 인프라 관점에서 서비스가 어떻게 배포되는지를 이해할 수 있었다.

* VPC, Subnet, Route Table은 각각 따로 보면 어려웠지만, Public과 Private 네트워크를 구성하는 하나의 흐름으로 연결해서 보니 역할이 명확하게 이해되었다.

* Spring Boot 서버를 인터넷에 직접 공개하지 않고 ALB와 Bastion Server를 활용하는 구조를 보면서 실제 운영 환경에서는 보안이 매우 중요한 요소라는 점을 느꼈다.

* React와 Spring Boot를 각각 분리하여 배포하고 ALB를 통해 연결하는 방식이 실제 서비스에서 많이 사용하는 구조라는 점이 인상적이었다.

</br>

#### [활용 방안]

* AWS에서 서비스를 구축할 때 Public Subnet과 Private Subnet을 구분하여 네트워크를 설계하기

* 운영 서버는 Private Subnet에 배치하고 Bastion Server를 통해서만 관리하도록 구성하기

* ALB를 이용하여 여러 Spring Boot 서버에 트래픽을 분산하고 안정적인 서비스 환경 구축하기

* React Frontend와 Spring Boot Backend를 분리 배포하여 역할을 명확히 나누고 HTTP API로 연동하기

* Route Table과 NAT Gateway를 적절히 구성하여 외부 접근은 최소화하면서 필요한 인터넷 통신은 허용하는 네트워크 환경 설계하기
