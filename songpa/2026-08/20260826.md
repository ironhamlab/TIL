
- 단원명 : ICT CoC 현장실습 및 프로젝트
- 학습 주제 : Service/Controller 계층과 프레임워크 동작 원리

---

#### [학습 내용]

* 의존성 주입(DI)과 IoC 컨테이너
  - Service/Controller가 `private final XxxRepository xxxRepository;` 필드를 갖는 것은 "직접 만들지 않고 외부에서 받아 쓰겠다"는 선언이며, 실제 객체를 채워 넣는 주체가 Spring의 IoC 컨테이너(`ApplicationContext`)다.
  - IoC(제어의 역전)는 "객체 생성 권한을 프레임워크가 갖는다"는 원칙이고, IoC 컨테이너는 그 원칙을 수행하는 실체이며, DI는 그 원칙을 실현하는 구체적 방법이다.
  - `@Service`, `@Component`, `@Repository`, `@Controller` 애노테이션이 붙은 클래스가 IoC 컨테이너에 Bean으로 등록되는 대상이다.

* JPA / Hibernate / JDBC / Spring Data JPA의 계층 관계
  - JPA는 "이렇게 다루자"는 표준 규격(스펙)이고, Hibernate는 그 규격을 실제로 구현한 라이브러리다. `@Entity`, `@Column` 같은 애노테이션 자체가 JPA 표준 API의 일부다.
  - `findById()`, `save()`는 순수 JPA가 아니라 Spring Data JPA가 얹은 편의 메서드이며, 내부적으로 JPA 표준(`EntityManager.persist()` 등)을 호출하고 Hibernate가 실제 SQL 생성/실행을 담당한다.
  - Hibernate는 위로는 JPA 규격을, 아래로는 JDBC(DB와의 실제 통신 규격)까지 연결하는 다리 역할을 한다.

* Controller 계층의 핵심 구성요소
  - `@RestController` + `@RequestMapping`으로 클래스의 역할과 기본 경로를 정의하고, `@PostMapping`/`@GetMapping` 등으로 메서드별 HTTP 메서드를 지정한다.
  - `@RequestBody`는 요청 JSON을 DTO 객체로 자동 변환해주는 표시이며, `ResponseEntity<T>`는 데이터+상태코드+헤더를 함께 담는, Spring이 미리 제공하는 응답 포장 클래스다.
  - `ResponseEntity` 없이 값만 반환하면 성공 시 자동으로 200, 예외 발생 시 자동으로 500이 붙으며, 201/400/404 같은 세밀한 상태코드는 명시적으로 지정해야 한다.

* Optional과 예외 처리 패턴
  - `Optional<T>`은 "값이 없을 수도 있다"를 타입으로 강제하는 안전장치이며, `.orElseThrow()`로 값이 있으면 꺼내고 없으면 예외를 던지는 방식으로 `Optional<T>`를 `T`로 안전하게 벗겨낸다.
  - Service의 조회 로직(`findById().orElseThrow()`)은 생성/조회/수정/삭제 전반에서 반복되는 기본 패턴임을 확인했다.

#### [느낀 내용]

- "Repository 메서드가 JPA다"라고 생각했던 게 착각이었고, 실제로는 Spring Data JPA(편의 계층) → JPA 표준 → Hibernate(구현체)로 이어지는 여러 계층이 겹쳐 있다는 걸 알게 됐다. 프레임워크를 "블랙박스로 쓴다"와 "계층을 구분해서 이해하고 쓴다"의 차이를 체감했다.
- Controller에서 반복적으로 쓰는 요소(애노테이션 4종 + 파라미터 애노테이션 2~3종 + ResponseEntity)가 사실 몇 개 안 된다는 걸 정리하고 나니, 처음의 혼란이 "배울 게 무한하다"가 아니라 "처음 보는 개념이 한꺼번에 쏟아졌을 뿐"이라는 걸 알게 됐다.

</br></br>

#### [활용 방안]

- 새로운 Spring 개념을 마주할 때 "이게 정확히 어느 계층(JPA 표준 / Spring Data JPA / Hibernate)의 것인지" 구분해서 이해하기
- Service 로직을 짤 때 `findById().orElseThrow()` 패턴을 기본 뼈대로 두고 시작하기
- Controller 작성 시 애노테이션의 역할(클래스 표시/경로/HTTP메서드/파라미터변환/응답포장)을 하나씩 짚어가며 채우기
